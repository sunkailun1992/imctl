## 需求与证据

用户对 build 135 的实际会话页截图指出：未知方向消息居中形成第三列；附件卡片重复显示协议状态、过期时间、按钮及原始错误；图片需再点一次才显示，视频需另开预览；两条图片显示不明的系统错误编号。仅在「文件传输助手」做只读复核，发送 0 条。当前 4 条图片行中，2 条因企微本机缓存缺失返回 `MEDIA_NOT_FOUND`，另 2 条媒体接口给出 `.png` 文件名，但对象内容实为 JPEG。后者导致下载的扩展名与文件头校验不一致，不能行内渲染。真人头像像素来源仍未确定，占位头像不能声称是真人头像。

## 修复范围

- 会话列表限制宽度，消息区改为单一滚动容器；已确认外发靠右，入站靠左，方向未知放中性左列并保留悬停提示，不再居中占一列。
- 图片到达会话视口时取回并直接显示在气泡中；视频点击封面或播放后，在原气泡内显示播放器。文件点一次即取回并交给本机默认应用。文件/视频不因滚动而批量上传，避免阻塞守护进程串行执行器。
- 卡片只留主动作、简短错误与按需操作菜单；不再展示签名 URL、原始 RPC 错误、消息标识、缓存内部状态和过期时间。`ControlError` 转成可操作的提示；缺缓存时说明需在企微先打开后重试。
- `message.media` 按缓存文件实际签名选择图片文件名扩展名，已知的错误扩展名改正，未知签名拒绝；控制台只读预览允许 HEIC 并校验文件头，`message.sendFile` 的既有格式白名单不扩大。
