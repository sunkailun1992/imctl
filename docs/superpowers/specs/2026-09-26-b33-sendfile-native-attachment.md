# B33：原生附件暂存信号与 MQTT 活体验收

## 背景与目标

1.0.13 的 `message.sendFile` 在本机企业微信 5.0.11 暂存合成 PNG 时返回 `LOCAL_GUARD: composer changed while staging attachment`。真实 AX 读回显示输入框值是单个 U+FFFC、字符数 1、唯一子元素为 `AXUnknown`；命令在 checkpoint 和回车前停止，消息历史无新行。旧代码把任何非空值一律当成人工文本。

只允许这个精确的原生附件形态通过暂存门，并在回车前复核同一会话、输入框与暂存状态。旧版空 `AXValue` 表示也只能有一个字符或一个原生子对象；粘贴前已有附件、普通文本、混合文本、多个对象或子元素不符均停止；模型不能替代这项校验。发送成功仍必须由新外发且类型吻合的消息行证明。回车后没有新外发行一律为 `unknown`，不自动清理输入框，以免覆盖人工编辑；幂等、checkpoint、策略、按键、权限和协议字段不变。

## 验收与边界

- Fake AX 覆盖原生占位成功、人工文本与错误占位拒绝、旧版空值下的多个对象拒绝、粘贴前残留附件拒绝、提交后证据不足保留输入框。
- `swift build`、`swift test`、敏感扫描通过。
- 只向用户授权的文件传输助手发唯一命名的合成 PNG / MP4 / PDF；每条只提交一次，MQTT、`command.get`、`event.replay` 和真实外发消息行对账。失败或 `unknown` 不换键盲重发。
- U+FFFC 与 `AXUnknown` 证明客户端出现一个原生附件对象，**不包含附件身份**。若客户端无法读到文件名，发送后仍只按协议指定的新外发行、类型和方向取证；不宣称像素级或文件字节一致。
