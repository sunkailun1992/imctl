# B36：发送前输入框暂存的两轮视觉观察

## 目标与边界

B34 已对非活动目标的选会话取得真实千问两轮活体证据；B33 的文本、图片、视频和 PDF 发送虽取得 MQTT、气泡与事件证据，但均走确定性 AX 路径，模型调用数为零。B36 只扩展显式 `message.send` 与 `message.sendFile` 在**目标会话已由 AX 严格确认**之后、不可逆提交之前的可逆准备阶段：暂存前观察一次经核验的企微主窗口，原动作层暂存固定请求内容，暂存后重新截图由模型复核，再由独立 AX 证据决定能否落 checkpoint 并按原路径提交。

这不是自由文本代理。模型不能选择收件人、改正文或文件来源、决定是否发送、执行粘贴或 Return，也不能把画面中的聊天文本当指令。`message.broadcast` 的逐目标子命令、其它方法、协议参数 / 结果 / 事件、策略与幂等语义均保持原状。本批规格与计划不授权新的活体发送。

## B28 证据边界与入口

1. B28 已证明：真实夹具只支持聊天视口下方**唯一可写 `AXTextArea`**；两个候选时无法独立证明哪个是聊天输入框，必须在任何写入、粘贴、checkpoint 和提交前失败。B36 不让模型从多个编辑框里猜一个，也不把模型判断作为附件身份凭据。进入视觉阶段前，动作层先按现有布局、role、frame、空值、目标标题、完整消息基线与策略证明唯一输入框；不满足时沿原错误路径停止，截图和请求均为零。
2. 仅显式外部固定命令且 `desktopCommandMethod` 精确为本方法、屏幕录制已授权、本机 `cloudEnabled` 与 `fullWindowEnabled` 同时开启、所选视觉提供商与密钥有效时进入。已通过命令执行器的暂停、速率、幂等、过期、目标白名单与策略检查。后台 watcher、自动申请、B15 本地方向判断、管理 / API 命令不进入。
3. 目标已活动时无需为选目标制造截图；若目标未活动，先完成 B34 的两轮选会话前缀，再对唯一输入框执行本批两轮。视觉关闭时保留现有 AX 发送路径，不能声称该次有模型参与。进入视觉路径后模型 `stop`、拒答、超时、授权 / 策略变化或客户端漂移均失败关闭，不悄悄退回纯 AX 发送。

## 两次观察与允许的动作

1. **暂存前**：冻结企微 bundle ID / PID、唯一主窗口句柄与 frame、严格活动目标、唯一输入框句柄 / role / frame。截取该企微窗口单帧；观察里只给已由 AX 独立证明的**唯一输入框匿名候选框**作为画面锚点，允许步骤限定为 `verify/reobserve/stop`，不得返回 `writeText`。模型只判断画面是否与固定的“当前会话输入框可准备”阶段相容；`verify` 只触发本机重读空输入框与命令准入，它不是模型批准发送。首次观察不提供任意坐标、文本或文件来源。
2. **固定暂存**：`message.send` 仍由原动作把请求里的原文一次写入 AX 输入框；`message.sendFile` 仍由原动作校验来源与文件头、准备 outbox、按已批准的 `⌘V` 粘贴一次并恢复剪贴板。模型既不产生正文也不触发键盘。暂存前再次核对方法、暂停 / 策略、活动目标、企微 PID / 窗口及输入框句柄、角色和位置。任何不符不暂存。
3. **暂存后**：重新定位相同企微主窗口并取得**新鲜**截图，向同一选定模型发起第二次观察；仅允许 `verify` / 重新观察 / 停止，不允许它提交。模型提出 `verify` 后，本机仍须重读相同目标与输入框：文本的 AX 值必须逐字等于请求原文；附件必须满足现有严格的单个原生对象 / U+FFFC 暂存守卫、文件来源校验与唯一附件类别预期。画面看起来像一个附件不能证明它就是请求文件；图片、视频、PDF 的身份与发送结果仍由原字节 / 类型校验及提交后新外发消息证据判断。
4. 两轮通过之后才进入原有 checkpoint、不可逆单次提交和客户端消息后验。`message.send` 在暂存后观察失败时，只有当前目标和同一输入框仍相同且 AX 值仍等于本次暂存原文，才可清理这段文本；人工改过的草稿必须保留。`message.sendFile` 暂存失败或第二轮失败不按 Return、不重复粘贴；企微中可能留下附件暂存界面，但外层清理会丢弃临时 outbox 文件，不能承诺这份草稿可供人工继续发送，需人工检查并清理。已提交后模型不得重发；缺可靠外发气泡继续返回 `unknown`，同幂等键只回放原记录。

## 轮次、安全和结果证据

- 沿用命令级最多 6 次视觉推理与 40 秒预算。非活动目标先占 B34 两轮，本批正常再占两轮；任何重观察都计入预算。每轮重核 PID、主窗口、方法、当前策略、目标、输入框和本机视觉三门；冻结窗口漂移、双输入框、草稿非空、候选句柄变化、模型错误或预算到期均停止。不能把异步 MQTT 等待超时理解为未提交；仍用原幂等键对账。
- 本批视觉链产生的全窗截图、Base64、模型提示词与原文回复只在当前调用内存中使用；不落盘，不进入日志、SQLite、MQTT、MCP、门报告或 wiki。模型密钥仍按既有本机配置保存，不进入这些输出。原命令的请求参数和发送 checkpoint 仍沿用现有持久化机制，可能包含请求正文或文件来源；本批不改变该机制。诊断计数只报告进程累计的截图、请求与 HTTP 200 次数；HTTP 200 和模型 `verify` 都不是命令成功证据。
- 成功仍要求原动作层的同目标、同内容、**新出现的 outbound** 消息行及相应文件类型 / 文件名规则、checkpoint 和 MQTT 终态。两次模型观察只证明该次固定发送流程确有受限视觉参与且未发现冲突，不能代替 AX 暂存证据或发送后验。

## 验收层次

| 层次 | 必须证明 |
|---|---|
| Fake AX + 假模型 | 唯一输入框、目标已活动时恰两次新观察；非活动目标时 B34 前缀加本批两次且总预算生效。首次 `stop` 时零暂存 / 零 checkpoint / 零提交；第二次 `stop` 或 AX 值不符时零提交、人工草稿不被清理。双输入框、已有草稿、策略 / 暂停 / PID / 窗口 / 目标 / 句柄漂移、缺授权 / 密钥及模型异常均在相应边界失败；视觉关闭沿原 AX 路径零云端请求。文件只粘贴一次，严格单对象守卫、剪贴板恢复、失败不再粘贴；提交后证据不足 `unknown`，同键不重做。 |
| 真实企微 + 千问 + MQTT | 使用稳定签名安装版，先核对六项本机授权、视觉三门与计数基线。取得**新的、明确目标与条数的发送授权之后**，分别对本人文件传输助手测试文本及附件进行活体：记录两次模型请求的差分、原文 / 单附件 AX 暂存证据、唯一一次提交、新外发气泡、`command.get` 与终态事件。未经新授权，本批实际发送 **0 条**，视觉发送链标“待活体”；B33 已用完的四条测试消息不能充当 B36 证据。 |
| 回归 / 发布 | `swift build`、全量 `swift test`、`ForbiddenAPITests`、敏感扫描、协议与随包文档检查；门报告分开写 fake、模型活体、客户端、MQTT、安装包与第二台 Mac。没有真实发送及两次计数差分，不能称 `message.send` 或 `message.sendFile` 的 B36 分支完成端到端验收。 |
