# B26：`contact.add` 打开添加客户窗口的可逆视觉轮次

## 范围与授权

仅限调用方显式发起的固定 `contact.add` 命令。手机号必须先通过本机 `contactAdd.allowedPhones`，`openContacts` 与 `addContact` 必须通过原策略。用户已允许固定桌面命令对经核验的企微主窗单帧使用所选云端视觉模型；本批不增加权限、提供商、协议方法或可发送内容。

模型只在“新的客户”右侧标题栏有多个符合 AX 条件的“添加”按钮时选择一个当前候选，最多 4 轮、2 次 `AXPress`、24 秒，且计入命令级预算。AX 唯一按钮保持零截图、零推理的原快路径。搜索手机号、输入问候、匹配来源、按匹配行“添加”、发送邀请与后验仍由原 `AddContact` 流程执行；模型不会得到手机号，也不能选择匹配或确认按钮。

## 候选、门禁和后验

- 候选必须是企微主窗中位于“新的客户”页面标题带、标题精确为“添加”的可按且启用 `AXButton`；右页标题必须由左侧 outline 之外的唯一 AXStaticText 证明。带“发送 / 邀请 / 确定 / 完成”语义的按钮不入候选。
- 每轮截图前、模型返回后及最终按压前，重读命令来源和方法、当前视觉许可、暂停与策略快照、手机号白名单、原始 `.openContacts` / `.addContact` 授权、企微 PID、应用与主窗句柄 / frame、当前通讯录页面及按钮句柄 / role / frame / 可按性。候选集仅来自当前 AX，不执行模型给出的坐标、文本或额外动作。
- 原先已有第二窗口或 sheet 时不进入视觉轮次。按压后只承认新出现的唯一企微第二窗口，其中 AX 标题精确为“添加客户”、只有一个空搜索框及一个关闭按钮，且没有邀请确认按钮。此证据成立后才进入原手机号搜索流程。
- 如果出现其它第二窗口，即使有关闭按钮也立即停止：AX 无法证明它属于本次按压，自动关闭可能影响用户同时打开的窗口。只有主窗中的唯一临时 sheet 具备精确“添加客户”标题、没有输入框且有唯一“取消”按钮时，才取消并读回关闭后继续。其它 sheet、取消未关闭、页面或权限漂移、轮次耗尽均停止。按钮未生效时可在预算内重新观察。

## 验收边界

Fake AX 和合成窗口测试覆盖快路径、两轮、错误窗口 / sheet 清理、未关闭停步、策略 / 手机白名单 / 方法 / 许可 / frame 漂移及普通 runner 拒绝 `press`。本批不触碰真实企微，不发送或邀请；真实歧义样本和云端请求仍须主任务单独做活体验收。
