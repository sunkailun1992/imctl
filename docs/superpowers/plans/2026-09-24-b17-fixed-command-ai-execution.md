# B17：固定桌面命令有界 AI 多轮执行计划

> 本页是目标实现计划，不是上线或活体验收回执。设计依据：`docs/superpowers/specs/2026-09-24-b17-fixed-command-ai-execution.md`。每项完成状态由当批门报告核对，不用“设计完成”替代运行证据。

## 全局约束

- 不增加自由文本 MQTT 命令、任意截图 RPC、全局鼠标或新按键。现有 `RPCMethod`、JSON-RPC 信封、MQTT topic、Response Topic 守卫、命令状态、幂等、checkpoint 和事件游标保留。
- 只有**显式固定桌面协议命令**可触发全窗云端视觉；先核验当前企微 PID / 窗口 / 命令目标。窗口单帧在内存中使用，不落盘、不出现在结果 / 日志 / 事件 / 夹具；后台 watcher、自动轮询和 B15 本机媒体方向零云端请求。
- 模型只在每个方法专属允许动作集合中选择候选 AX 元素；执行前后重读，不接受任意坐标、文字操作指令、目标 / 正文 / 成员 / 策略 / 幂等键变化。不可逆前 checkpoint；不可逆后不确定用 `unknown`，绝不自动换键重试。
- 默认提供商千问；整窗视觉当前可在本机切换千问 / Gemini，DeepSeek 配置仍保留但不支持整窗规划。仅官方固定 HTTPS 端点，禁止重定向、跨提供商自动转发和从 MQTT 传密钥 / URL。全窗路径同时要求屏幕录制授权、`cloudEnabled` 和独立的 `fullWindowEnabled`；旧配置缺整窗字段默认 false，本机 `imctl vision full-window --enable|--disable` 可更改，控制台设置 / 状态显示。
- 开发测试仅用合成窗口、fake AX、fake API 与假密钥；活体仅测试目标，记录真实模型请求数和客户端证据，不保留截图。门报告逐方法列“未接入 / fake 通过 / 活体通过”。

## Task 1：定义方法、步骤与候选的类型边界

1. 为当前桌面命令列静态方法矩阵：`account.status`、`conversation.list/read`、`message.history/send/sendFile`、`client.navigate`、`contact.list/request.list/request.accept/add`、`group.create/rename/addMembers`、`broadcast.confirm`。区分只读、可见导航、可逆写入、不可逆提交及各自的成功证据；`message.broadcast` 在子 `message.send` 上复用。列明 `policy.*`、`command.*`、`controller.*`、`event.replay`、`message.media`、其余企微 API 与 watcher 排除。
2. 用类型封闭本轮候选 ID、允许的 AX 动作与停止原因。候选只能来自刚读取的 AX 树，不能来自模型构造的元素引用或坐标；同一候选 ID 在新观察轮次不复用。
3. 测试：每个方法只能枚举本方法动作；未知方法 / 越界动作拒绝；同屏跨会话候选不可使用。记录方法覆盖矩阵，不把枚举定义本身算作端到端接入。

## Task 2：经核验的单窗口截图与模型交互

1. 复用 `WeComScreenCapture` 的窗口 PID 与 frame 核验能力，扩展为**只取当前企微窗口**的单帧图；下采样与 JPEG 编码均在内存中，显式设置像素 / 字节上限。截取前后比对 PID、窗口、活动会话与当前命令。不能核验即不上传，绝不退到整屏或其他应用。
2. 复用本机 `CloudVisionSettings` 的提供商、模型、启用状态和独立密钥；按所选模型的官方格式送**内联图片**与固定任务说明，不提供可调用的工具，不接受 API 跳转。给请求、响应、每命令轮次与总耗时上限；不在后台重试或换提供商。
3. 测试：合成图标记企微窗外像素，解码实际请求图片确认标记像素为零；PID / frame / 会话变化、未授权、关闭开关、缺密钥、429、超时、过大图 / 响应、畸形 JSON 均无 AX 写。日志 / 错误 / 结果不泄漏 Base64、密钥或原始模型正文。

## Task 3：有界观察 → 选择 → AX 动作 → 再观察循环

1. 命令处理器提供当步目标、匿名 AX 候选、角色、动作、可观察后验事实；模型返回的候选 / 动作先经过类型验证，再经过实时 AX 与窗口复核。AX 唯一且可靠时走直接路径，避免多余上传和 UI 等待。
2. 每轮仅执行一个允许的 AX 属性 / 动作或已有批准的 pid 级按键；之后读取新状态，决定完成、进入下一轮或停止。提示词注入、伪造候选、模糊答案、旧窗口 / 旧会话及超预算都停止；不能因模型“说成功”改变终态。
3. 测试覆盖两轮成功、无把握拒绝、旧候选拒绝、达到轮次 / 时间上限停止、AX 动作后后验事实缺失，且调用次数有上界。循环内部不得直接跳过 `CommandExecutor`。

## Task 4：逐方法接入与结果语义

1. 将 Task 1 的方法逐一接入 typed loop；每个方法保留原 params 与结果字段、暂停 / 目标 / 白名单语义。读取类以客户端可复核的 AX 值形成返回；导航类确认活动视图；发送、联系人与群动作沿现有提交与证据流程。
2. 在 `CommandExecutor` 的检查之后才可截图或模型调用。发送 / 发文件 / 接受 / 建群 / 改群 / 加群成员 / `broadcast.confirm` 的不可逆动作必须先 checkpoint；已提交而证据不足返回 `unknown`，同键只回放，不再次驱动模型或 AX。旧 `broadcast.confirm{msgid}` 用稳定派生幂等键保持请求兼容；它还需在助手 AXSheet / 独立窗口读到精确 `msgid` 且仅有一个发送按钮，才可落 checkpoint 并按按钮，模型不能替代任务关联。`message.broadcast` 每个子命令各保留独立记录与间隔。
3. 用 fake AX 对**每个方法**建立至少一条多轮正常路径和失败路径，另建统一越权 / 截图 / 注入 / 崩溃恢复矩阵。不要为了满覆盖而退化成对空页面调用模型；不能实装或缺测试的方法在门报告列为未接入。

## Task 5：MQTT、MCP 与文档契约

1. 保留现有同步 MQTT 处理、Response Topic 限本机子树、Correlation Data 回显、`/evt` 持久游标。命令仍回原 `CommandRecord`；如确有新增可选结果字段 / 错误码，同提交更新 `docs/protocol/im-control-protocol.md` 与 `ProtocolDocTests`，并对旧客户端解码做测试。
2. 测试模型多轮导致 MQTT 调用方等待超时：响应丢失 / 重连之后，用原幂等键只得到原命令，`command.state` 终态与 `command.get` 可对账；后台事件泵不依赖响应是否送达。CLI 默认等待 90 秒，业务侧较短等待超时后仍须对账，不把超时当作“未执行”。
3. 同步 README、`AGENTS.md`、安全 / 测试规范、控制台与授权文案、协议、第二台 Mac 安装说明；旧 B16 门报告只保留历史事实，不改写为 B17 结果。

## Task 6：构建、活体与交付门

1. `swift build`、`swift test`、`bash scripts/check-secrets.sh`、`git diff --check` 与签名构建；区分全量结果和单项结果。验证运行文件 0700/0600，安装包不包含密钥 / 截图。未通过的项如实写入门报告。
2. 在本机稳定签名应用执行显式只读 MQTT 方法，记录选定提供商 / 模型、请求次数、轮数、响应时间、AX 证据、MQTT `commandId` / 终态事件；确认后台观察零请求。Gemini 如仍遇服务地区限制，只标不可用，不自动切其它端点。
3. 只对本人测试号与只有本人的测试群做受控写入；逐方法记录提交次数、模型参与、客户端结果、`unknown` 对账、发送条数。不做真实联系人 / 客户群尝试。无法实测的命令标“待活体”，整体不得称全范围验收。
4. 根据门报告实际覆盖决定是否构建 / 替换安装及第二台 Mac 包；更新仓库与 wiki 的事实口径时分开记代码、单测、合成 API、真实客户端、MQTT 与第二台 Mac 证据。
