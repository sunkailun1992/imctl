# B34：企微固定命令的真实多轮视觉选会话

## 背景与本批目标

B17 建立了经核验的企微窗口截图、千问 / Gemini 候选决策与方法动作上限；B18–B26 在解析遗漏或控件歧义时接入了若干可逆轮次。B33 的 MQTT 活体验收中，真实企微整窗截图、云端请求与模型轮次均为零。因此，已有发送与读取成功记录不能证明模型参加了客户端控制。

本批先让显式 `conversation.read` 完成一条可实测的“企微窗口观察 → 模型选择 AX 行 → 客户端选中 → 新窗口观察 → 模型提出复核 → 新鲜 AX 证据 → MQTT 结果”链。目标是针对企微固定协议命令逐步扩展有界规划；本批不宣称所有桌面方法已有跨步骤视觉规划。`message.send`、`message.sendFile`、`group.rename`、`group.addMembers` 只复用目标会话选中前缀，它们后续的编辑、粘贴、确认和提交仍由各自原动作实现。

## 入口、候选与模型权限

1. 入口限 MQTT / MCP / 本地调用明确发起的固定桌面命令。`desktopCommandOrigin`、当前 `RPCMethod`、暂停 / 策略 / 目标检查必须先通过。后台 watcher、自动申请、B15 媒体方向识别、`policy.*`、`controller.*`、`event.replay` 与企微官方 API 不进入本路径。
2. 企微目标已经激活时直接读取并核对 AX 活动头部，不为制造模型请求而切换。目标尚未激活、屏幕录制已授权、本机 `cloudEnabled` 与独立 `fullWindowEnabled` 已启用时，`conversation.read` 对**视口内有对应像素的 AX 行**进入主动视觉选会话；解析器已识别唯一可见 AX 行也进入本路径，以取得真实模型选择与动作后视觉复核。已解析但离屏的行继续走原 AX 路径，不让模型选择没有对应像素的候选。未启用整窗视觉时沿原 AX 路径执行；进入视觉路径后模型错误、拒答或授权撤销均停止，不在同一命令里悄悄改用另一家模型或猜选行。
3. `conversation.read` 的目标仍来自原 `target` 参数及身份桥。唯一精确 AX 标题行存在时，仅该行可作为 `selectRow` 候选；两个精确同名行返回 `TARGET_AMBIGUOUS`。AX 标题缺失但会话表有可操作、可见的 `AXRow` 时，模型可从**当前企微会话表的 AXRow 候选**中选一个；选中后必须从新鲜 AX 活动会话头部严格读到请求标题，平台 ID 目标还须通过原身份桥核对，才可返回该会话的读取结果。选错可能短暂切到其它会话；标题不符、目标身份漂移或读不出头部即停止，不读取或返回错行消息，也不触碰输入框或发送。纯像素可见但没有可执行 AX 行 / 动作的控件不受支持，不增加任意坐标点击或合成鼠标。
4. 四个目标写入命令只允许**唯一精确 AX 标题行**作为模型候选；AX 标题缺失或同名时不得借模型猜哪个是发送目标。原写入动作的策略检查在任何截图与选行之前完成，视觉前缀返回后还要重新核对活动头部和原目标身份，才进入各命令原有流程。

## 两轮以上的执行与结果证据

1. 第一轮观察只截当前经企微 bundle ID、PID、AX 主窗口句柄和 frame 核验的窗口单帧；整条命令冻结此窗口身份并逐轮重核。模型得到固定目标、当前相位、匿名 AX 候选及允许的 `selectRow` / `reobserve` / `stop`；不能生成坐标、收件人、正文、文件、群名、成员、策略或按键。选中前再次核对 PID、窗口、候选句柄、角色、AX 动作、位置、目标和策略，随后仅对会话表执行 `AXSelectedRows`。全表解析行与原始 AX 行的同名检查包含离屏行。
2. 选行后读取新鲜 AX 活动头部，但**即使已经读到目标，也不能在主动视觉路径直接结束**。另截一帧当前已核验的企微窗口，向同一选定模型发起独立的动作后观察轮次。该轮只允许 `verify` / `reobserve` / `stop`，不允许新的目标、输入框写入或不可逆操作；`verify` 仅请求本机执行既定后验检查，模型文字本身不构成成功证据。正常成功路径至少有两次真实模型请求和两帧新观察，第二轮发生在 AX 选行之后。
3. 只有第二轮未拒绝、且新鲜 AX 活动头部严格等于目标并通过身份 / 策略复核，`conversation.read` 才能返回原有 `{active, messageCount, composerPresent, conversationType, …}`。若首次 `AXSelectedRows` 未落实，可在轮次上限内重新观察和再选，随后仍须进行动作后视觉观察与 AX 复核。最多两次选行、六次模型轮次、整命令视觉预算 40 秒；到期、窗口变化、候选漂移、模型 `stop`、提供商错误均停止。客户端可能已发生可逆选中，但不得把未核实状态返回为成功。
4. 四个写入命令复用上述可逆前缀后，依旧由原动作层准备、落 checkpoint、提交一次并取得客户端证据。模型动作后 `verify` 不能代替消息气泡、群名、成员数等原后验；不可逆提交后的证据不足继续为 `unknown`，同幂等键回放不重做。`message.broadcast` 仍按各 `message.send` 子命令原有策略与幂等路径处理。

## 数据、诊断和协议边界

- 全窗上传仍要求屏幕录制、`cloudEnabled` 和 `fullWindowEnabled` 三门同时成立。图片在内存中处理，仅送当前选定的官方固定 HTTPS 端点；不保存截图、Base64、原始提示词 / 回复、聊天正文或 AX 全树，不进入 SQLite、日志、MQTT、MCP、门报告或 wiki。没有跨提供商自动重试；DeepSeek 仍不支持本整窗流程。第三方会收到整张企微窗口，其中可能有其它会话信息。
- 仅在进程内维护匿名累计 `captureCount`、`requestCount`、`successCount`，由 `controller.describe` 以 `visionCaptureCount`、`visionRequestCount`、`visionHTTP200Count` 三个字符串数值只读展示。活体验收在显式命令前后读取差值，以区别合成 API、真实窗口、模型调用和客户端结果。内部 `successCount` / 对外 `visionHTTP200Count` **只计固定官方端点返回 HTTP 200 的次数**，在 JSON / 模型决策解析之前计；它不代表有效选择、AX 后验或企微命令成功。最终以 AX 后验、MQTT 命令终态和事件为准。三个计数不持久化，不含截图、目标或模型原文。
- 不新增自由文本代理方法、截图 RPC、按键或模型可修改的命令参数。`conversation.read` 及四个写入方法的对外参数 / 结果、JSON-RPC 信封、MQTT topic、Response Topic 守卫和幂等语义保持原样；`controller.describe` 增加上述非敏感诊断字段时，同一提交更新协议文档与契约测试。

## 验收与后续范围

| 层次 | B34 验收证据 |
|---|---|
| Fake AX / 假模型 | 唯一已解析行也至少两轮；AX 标题缺失时模型只能选可见 AXRow，选错后严格标题拒绝；四个写入方法只有精确标题行；动作后新帧、模型 `verify` 与独立 AX 后验；授权 / 策略 / 暂停 / PID / 窗口 / 候选变化阻断后续 AX 写；预算、注入与无候选失败关闭。 |
| 真企微 + 真千问 + MQTT | 稳定签名安装版、三门授权、本人的文件传输助手；先使它不是当前活动会话，再用显式 `conversation.read` 选中。命令前后 `controller.describe` 数值差分证明至少两帧、两次真实请求，读取响应与事件证明终态，新鲜 AX 头部证明目标。该验收不发送消息。 |
| 回归 | `swift build`、全量 `swift test`、`ForbiddenAPITests`、secret 扫描、协议测试；后台 watcher / B15 路径零云端请求；旧 AX-only 路径、同键回放与提交后 `unknown` 不回归。 |

`account.status`、`conversation.list`、`contact.list` 等纯读取方法仍以结构化 AX 事实为准；`message.history` 保持已有滚动条歧义轮次；`client.navigate` 的 macOS 菜单位于获准的企微窗口画面之外，不扩大截图权限；`contact.*`、`group.create` 和 `broadcast.confirm` 仍按现有有限视觉后备或 AX 流程工作。后续批次须逐方法补齐可用候选、状态阶段与真实企微证据后，才能称该方法完成多轮视觉规划。本批门报告必须分开记录源码、fake、真实模型、真实窗口、MQTT、本机安装与第二台 Mac 的证据。
