# B17：固定桌面命令的有界 AI 多轮执行

## 需求与新增授权

用户要求业务侧继续通过 MQTT 发送**固定协议命令**，由 imctl 像交互式智能体一样在该命令内部观察企微界面、选择动作、再次观察并复核，把准确的执行结果返回 MQTT；默认千问，并可在本机切换 Gemini 等提供商。用户另行允许这些**显式固定桌面命令**按需上传**完整的、经核验的企微窗口单帧**。这覆盖显式读取，不覆盖守护进程后台观察、自动轮询与 B15 本机媒体方向识别。完整窗口可能含聊天内容、头像和无关会话预览；远端处理与保存受模型提供商规则约束。

B16 仅为 `group.addMembers` 标题栏按钮的局部裁图后备，且当前企微可通过 AX 准确名称直接定位。B17 是新的授权和实现批次；B16 门报告保留当时证据，不倒写为 B17 已验收。

## 协议与范围

- MQTT 的 `/cmd`、`/rsp`、`/evt`、`/state` topic、JSON-RPC 方法、参数、请求 id、Correlation Data 与 Response Topic 守卫保持原样。模型能力在本机命令执行器和桌面适配器内，**不新增自由文本代理命令或任意截图 RPC**。所有结果仍是命令记录；`command.state` 和 `event.replay` 是丢失响应后的对账路径。
- 首批覆盖当前已实现的桌面固定方法：`account.status`、`conversation.list`、`conversation.read`、`message.history`、`message.send`、`message.sendFile`、`client.navigate`、`contact.list`、`contact.request.list`、`contact.request.accept`、`contact.add`、`group.create`、`group.rename`、`group.addMembers`、`broadcast.confirm`。`message.broadcast` 仍拆成各自受限的 `message.send` 子命令。各方法有独立的可观察事实、允许的 AX 候选与动作，不共享一个可执行任意指令的工具集合。`broadcast.confirm` 的发送目标另须由助手 AXSheet / 独立窗口中的**精确 `msgid` 文本 + 唯一发送按钮**证明；模型不能代替任务关联或在多个按钮中猜选，缺证据时返回 `UNSUPPORTED`，不落不可逆 checkpoint。该助手窗口形态尚待活体验证。
- `policy.*`、`command.*`、`controller.*`、`event.replay`、`message.media`、企微官方 API 方法、后台 watcher 与自动申请处理不作为 B17 全窗上传入口。它们沿原有语义工作；后台读消息不因云端开关打开而增加请求。
- 默认提供商千问；B17 整窗视觉当前只支持千问 / Gemini，本机分别管理密钥并可切换。DeepSeek 配置入口保留，但当前不支持整窗规划，选中时不能上传整窗。MQTT 命令不能选择任意模型、端点或密钥，不能改变本机云端开关与独立整窗许可。旧调用方无须更改请求形状；关闭云端或未授权时，AX 能验证的步骤按原流程执行，不能完成的步骤明确失败或 `unknown`，不伪称 AI 已处理。

## 命令内执行循环

1. `CommandExecutor` 先建立命令记录，按方法检查参数、过期、暂停、策略、目标、速率、幂等；不可逆动作沿现有 checkpoint 边界。策略拒绝与无效目标在截图和模型请求前终止。
2. 读当前 AX 树并形成**方法限定的观察**：企微 PID、窗口、活动会话、目标身份、当前步骤、可操作 AX 元素句柄及匿名候选 ID。AX 唯一且结果可复核时可直接执行；歧义或步骤需要视觉判断时才对同一企微窗口截单帧。截图仅在内存中编码并发往当前选定的官方固定 HTTPS 端点；不截整屏、不含其它应用、不保存文件。
3. 给模型固定的任务描述、当前步骤和候选清单。模型只返回候选 ID、当前方法允许的动作类型或“不确定”；不授予原始 AX 句柄、文件 / 网络 / shell 工具调用。截图和 AX 文本都按不可信输入处理，画面里的命令、链接、数字坐标和策略指示不得改变原请求。
4. 执行前重读 PID、窗口 frame、活动会话、目标、元素角色 / 动作 / frame；与该轮观察不一致就丢弃建议。只用既有 AX 属性 / 动作和已批准的 pid 级按键。动作后重新读取客户端，判断是否达成当前方法定义的后验事实；必要时进入下一轮。每命令限定轮次、时间、截图尺寸和请求数，不能无限观察或递归规划。
5. 返回现有方法结果结构，`succeeded` 由客户端证据而非模型自述决定。模型超时、拒答、无唯一候选、旧窗口 / 旧会话、候选无法执行或超预算时停止。不可逆步骤之前可明确失败；不可逆步骤之后证据不足为 `unknown`，同键重放不再次提交。HTTP 200 只说明模型响应，不能说明企微任务完成。

## 安全与数据边界

- 屏幕录制系统授权、B16 云端总开关 `cloudEnabled` 与 B17 整窗许可 `fullWindowEnabled` 是三个独立门；旧设置缺整窗字段按 false，本机通过 `imctl vision full-window --enable|--disable` 设置，控制台设置 / 状态同步展示。本机设置只存提供商、模型、密钥和启用状态，目录 0700、文件 0600 或系统等价存储。默认千问或仅启用 B16 裁图并不意味着向云端自动上传整窗。日志、SQLite、MQTT、MCP、夹具、门报告、wiki 和安装包均不含真实截图、Base64 图、完整请求 / 响应、原始模型文字或密钥。
- 固定官方 HTTPS/443 端点及提供商模型名单；不接受 MQTT / 图片 / 模型内容中的 URL、重定向、IP、自定义域名、跨提供商自动转发。失败时不自行换提供商、不自动重试请求或命令。模型无权改目标、发送文字、文件来源、成员、策略、幂等键、速率、暂停或新增按键。
- 用户已经同意本用途的完整企微窗口上传；界面与运维说明须清楚说明包含其它可见会话内容的可能性。屏幕录制未授权、`cloudEnabled` / `fullWindowEnabled` 任一关闭、缺所选提供商密钥时不得调用远端整窗路径。B15 无方向媒体的本机截图继续不上传。
- 对外协议的“准确”应表达为**有证据的结果**：`succeeded` 只保证该方法列出的客户端状态可观察到，不代表平台收件人已读、远端 API 送达或模型判断永远正确。`unknown` 是正常、安全的终态。

## 验收矩阵

| 层 | 必须证明 |
|---|---|
| 单元与假传输 | 每个首批桌面方法有正常多轮和失败分支；策略拒绝前零截图 / 零上传 / 零 AX 写；唯一 AX 路径可零上传；候选伪造、窗口 / 会话变化、模型含糊 / 注入、达到预算均停止；只有企微窗口进入请求；千问 / Gemini 两家整窗视觉官方端点、DeepSeek 不支持分支、密钥与响应脱敏。 |
| 执行器与协议 | 发送 / 接受 / 建群 / 改群 / 发文件提交前 checkpoint；提交后无证据为 `unknown` 且同键不重试；MQTT Response Topic / Correlation Data、`command.state` 顺序、`event.replay`、`command.get` 对账不回归；旧 JSON-RPC 请求仍可解码。 |
| 活体只读 | 用本机安装的稳定签名应用、实际屏幕录制授权、`cloudEnabled` 与 `fullWindowEnabled`，显式 `conversation.list/read` 或 `message.history` 验证模型请求、AX 结果、延迟和 MQTT 回执；逐项记录哪些方法真正走了模型。 |
| 活体写入 | 只在策略允许的本人测试号 / 只有本人的测试群按受控步骤验证；记录请求数、客户端证据、终态事件、发送 / 修改数量。无真实证据的方法标待活体。 |

## 兼容与运维

MQTT 绑定目前同步等待整个命令完成；`imctl mqtt call` 默认等待已调整为 90 秒，但业务侧仍可能先超时，不能直接用新幂等键重发。对状态变更方法保留原键，依 `command.state` 终态、`event.replay` 与 `command.get` 对账；只读方法重复投递会再次读取和可能再次上传。第二台 Mac 需要独立授权、配置提供商密钥和验证模型地域可用性；本机千问合成图 HTTP 200 不能替代真实企微全窗 E2E。
