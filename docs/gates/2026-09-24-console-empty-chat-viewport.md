# 控制台切换会话后消息区空白门报告（2026-09-24）— 代码与本机安装通过，build 150 窗口待点检

## 条件与故障证据

- 用户在 1.0.3 build 149 控制台选中测试号私聊，消息区显示空白；文件传输助手能显示记录。本批只读检查，没有发送消息或更改策略。
- 同一会话的守护进程日志显示 `conversation.read` 和 `message.history` 均成功，后者返回 3 行。独立只读 `message.history(limit=30, scrollback=false)` 也返回 3 行，约 0.137 秒，且没有部分结果或错误。因此该次空白不能归因于消息读取超时或后端返回空数组。
- 在控制台先进入「日志」再返回「会话」后，这 3 行才出现在消息区。该现象与 SwiftUI 聊天 `ScrollViewReader` / `LazyVStack` 保留了前一条较长会话的滚动视口、切换到较短会话后仍停在没有行的区域相符。此处是根据活体表现和视图实现作出的归因；不能据此断言所有空白会话都具有同一原因。

## 实现范围

- 控制台把活动会话标题与最近一次正常历史读取的修订号组成消息视口标识。切换会话或成功取得最新一页消息时，重建 `ScrollViewReader` 并定位到最新行；显式回溯历史不推进修订号，以保留用户在旧消息中的位置。
- `message.history` 成功却返回 0 行时，消息区显示「未读到消息行」及稍后重试提示，不把一次 AX 空结果解释为会话本身没有消息。后续读取成功会清除提示。
- 变更仅在 `imctl-console` 的模型和视图；没有修改企微 AX 读取、守护进程、MQTT 协议、媒体地址模式、发送、策略、白名单或运行数据。
