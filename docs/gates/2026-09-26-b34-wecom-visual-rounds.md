# B34：企微选会话两轮视觉链活体验收（2026-09-26 CST）— 限定范围通过

## 范围和版本边界

本批验证显式 MQTT `conversation.read` 对**非当前**「文件传输助手」的选会话链：真实企微主窗截图 → 千问视觉选择可操作 AX 行 → 本机选行 → 新鲜截图模型复核 → AX 活动标题验证 → MQTT 终态。`message.send`、`message.sendFile`、`group.rename`、`group.addMembers` 复用选目标前缀，但本批只做 fake 测试，没有对四个写命令做真实模型活体写入。其它桌面方法未据此认定已支持主动多轮视觉规划。

活体安装与重装使用 `~/Applications/imctl.app` **debug build 185** 和稳定签名。build 号取自当前 Git 历史，故提示词修正前后的两个 debug 二进制同标为 build 185；下表分别记录，不能把初次失败算进修正后成功。未发布最终 release，也未在第二台 Mac 安装。测试没有发送消息、修改群或提交附件。

## MQTT 活体过程与独立后验

| 次序 | 视觉计数和结果 | 客户端 / 协议证据 |
|---|---|---|
| 初次 debug build 185 | 非当前文件传输助手的真实 MQTT `conversation.read` 使 `visionCaptureCount` / `visionRequestCount` / `visionHTTP200Count` 各增加 1；模型选择 `stop`，命令以 `UNSUPPORTED` 失败。 | 没有执行 AX 会话切换；HTTP 200 只表示官方端点应答，不表示模型选择或读取成功。 |
| 精确 AX 证据提示修正后，重装 debug build 185 | 守护进程重启后的 `controller.describe` 基线为 **0 / 0 / 0**。对非当前文件传输助手再发一次真实 MQTT `conversation.read`；命令 `D03E3DD1-D025-41D1-93F1-A0441ACE1AF9` 约 **9.8 秒**到 `succeeded`，读回 `active=文件传输助手`、`messageCount=20`。随后三项计数为 **2 / 2 / 2**。 | `account.status` 独立 AX 读回活动会话为文件传输助手；`command.get` 查同一命令为 `succeeded`。后台再次 `controller.describe` 仍为 **2 / 2 / 2**，没有额外视觉请求。 |

修正只使**唯一、可见、AX 标题与固定目标精确相等**的候选得到明确的模型选择指引；若画面明显冲突，模型仍可 `stop`。只读命令中 AX 标题缺失的可见候选不获得这项精确匹配证据。动作后的模型 `verify` 只请求本机继续检查，不能自己宣布成功；最终结果仍要求新鲜 AX 活动标题与目标严格相等。截图、模型原文、聊天正文和密钥没有写入 MQTT 响应、门报告或日志。

三个诊断数值是**守护进程启动以来的进程级累计**：截图次数、模型 HTTP 请求发起次数、固定官方端点 HTTP 200 次数。修正后前后差分 **2 / 2 / 2** 与两轮截图和两次模型请求一致；单看 HTTP 200 不能证明有效选择、AX 后验或命令成功。这里用 MQTT 命令终态、`command.get` 和独立 `account.status` AX 读回共同核对最终结果。活体发送数为 **0**。

## 1.0.14 debug build 186 回归复核

后续 B35 的候选 AX 父链读取改动与 B36 合并后，用稳定签名的 1.0.14 debug build 186 在同一安装位做只读复核：守护进程视觉计数基线 **0/0/0**；MQTT `conversation.read` 从文件传输助手切到 `imctl测试群`（命令 `375FFE52-F595-4F87-9B5A-8C33A20FF445`，`succeeded`，约 7.8 秒，活动标题及 3 条可见消息由 AX 读回），计数到 **2/2/2**。再由同方法切回文件传输助手（命令 `6B0B00BB-2514-47E7-B758-088744FCE043`，`succeeded`，约 10.1 秒，AX 读回活动标题），计数到 **4/4/4**。两次均为固定只读命令，未发送或修改群；截图和模型响应未保存。这证实本机当前企微 AX 父链仍可完成 B34 的两轮选择与复核，不推定其它写入方法通过。

同一源码的 **release build 186** 安装后又执行相同的两次只读切换：`A3FEA87A-50A9-4C98-9A4E-91E0EAE7746C` 与 `6601F82C-2574-4F2D-B3B7-5616C76F71B0` 均 `succeeded`，活动标题依次为测试群和文件传输助手，视觉计数从重启后的 **0/0/0 → 4/4/4**。这独立验证优化构建的选会话视觉链，仍不等于写命令验收。
