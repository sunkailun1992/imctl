# B25 消息滚动条边缘 AX 证据

## 问题

1.0.10 build 166 的显式 MQTT `message.history{limit:1}` 在本人文件传输助手的 12 次只读调用中有 10 次成功、1 次 `CLIENT_UNAVAILABLE`、1 次约 26.8 秒后返回 `UNSUPPORTED: message history visual round: timeout`。脱敏 AX 树只读快照显示消息滚动区为 `x=311, width=1609`；两个直属可写竖向滚动条分别在右边缘 `x=1904, value=1` 与内容内部 `x=1743, value=0`。后者使普通最新读取误判为歧义，进入云端轮次。

## 行为

- 在现有消息滚动区的直属 AX 可写竖向滚动条中，先用父区的几何证据识别右边缘、从顶部开始并覆盖至少四分之三高度的轨道。存在此类轨道时，内容内部的轨道不参与消息历史滚动与模型候选。
- 没有可识别的边缘轨道时，保留原候选集和 B21 有界视觉轮次；两个真正不同的边缘轨道仍交给模型。不能只凭模型自评宣称已到最新，必须读回滚动条值。
- 普通 AX 快路径零截图、零模型请求。只读历史命令以外不调用本路径；策略、暂停、PID、窗口、会话身份与已有预算门禁不放宽。
- 不记录企微正文、截图、联系人、附件 URL 或云端密钥。新增代码不改变 MQTT 参数、结果、事件或错误码。

## 验收

Fake AX 覆盖右边缘已是最新但内部轨道为 0 的场景、右边缘未到最新但内部轨道为 1 的场景，以及两个不同边缘轨道仍进入 B21 模型轮次。全量测试、签名包安装与只读 MQTT 结果分别记录；一次成功不能证明间歇性故障消除。
