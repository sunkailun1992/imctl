# B37：群名编辑前后受限视觉观察

## 范围

仅显式 `group.rename{target,name}` 在策略和目标会话核验通过后，给原有群名编辑动作增加两次只读视觉观察。若目标原本不活动，B34 的选会话视觉前缀仍先运行。模型只可在准备与写值读回两个阶段返回 `verify`、`reobserve` 或 `stop`；它不能选择新群、提供群名、写值或确认。`group.create` 继续原 AX 路径。本批不变更协议参数、策略、checkpoint、幂等或提交后验。

## 固定身份与两轮

1. 写值前，动作层须证明原群名、唯一选中旧群行、同一可写 `AXTextField` 位于右侧标题带。冻结企微主窗口句柄、PID、位置和该字段句柄、角色、位置及原值；右标题带出现第二个可写字段则停止。还要确认无模态窗口、没有第二个企微窗口，显式命令、本机录屏权限和视觉双开关有效。
2. 第一帧只给这一个 AX 字段框作画面锚点。模型 `verify` 后本机重新检查策略、暂停、命令预算、旧群选中行、窗口、字段、原值及视觉配置，原动作才按请求 `name` 写入。原有“首次写值不保持时最多一次同字段重写”仍在每次写前复核。
3. 最终写值逐字读回后重新截取当前企微窗口，第二帧只供只读复核。标题栏可能提前回显请求名，但此时选中的会话列表行必须仍是原群；若列表行换成其他目标，停止。模型 `verify` 后再读同一字段的精确请求名、同一旧群行、同一窗口与配置，才进入原 checkpoint 和最多一次 `AXConfirm`。
4. 任一观察拒答、超时、授权 / 策略变化、字段歧义、目标或窗口漂移，都在确认前停止，不降级为纯 AX 提交。第二轮失败时可能留下未确认的群名草稿，不自动覆盖人工编辑。确认后仅以**唯一选中行**变成请求名为成功证据；缺证据沿原不确定性语义，不由模型自评决定。

## 上限与验收

沿用显式命令最多 6 次视觉推理和从命令入口起 40 秒预算，包括 B34 前缀、重观察与本批两次观察。截图与模型原文只在内存，诊断只累计截图 / 请求 / HTTP 200 次数。真实窗口可包含聊天信息，仍按用户已批准的整窗上传设置和既有安全门执行。

Fake AX 与假模型应证明两张新截图、一次固定写值、一次 checkpoint 和最多一次确认；首轮/次轮停止、非法模型动作、缺录屏权限、双编辑框及选中行/字段/策略漂移都不得确认。真实企微加千问的群名写入须另有本批明确目标与次数的活体授权、安装版计数差分、MQTT 事件及客户端列表行后验；fake 通过不代表活体验收。
