# B21：`message.history` 歧义滚动条的有界视觉轮次

## 范围

显式 `message.history` 仍用 AX 读取活动会话消息。普通读取先回到最新位置；`scrollback:true` 在已加载消息少于所请求条数时向上加载，再尝试回到底部。只有当前消息区域暴露两个以上**位置不同的可写竖向滚动条**、并且当前命令具备 B17 整窗许可时，才用 B18 可逆轮次选择其中的 AX 候选。唯一滚动条、几何重合的重复滚动条和已在最新位置的普通读取沿 AX 路径，不上传截图。

模型不决定滚动量、会话、读取条数或成功结论，只能返回当前候选 ID 的 `scroll`，或者重新观察、请求核验、停止。实际写入固定为最新位置 `AXValue=1` 或向上加载 `AXValue=0`。每轮读取企微窗口、活动会话和滚动条；模型返回后及最后写入前重验命令来源 / 方法、暂停、本机云端与整窗许可、当前策略、目标身份、窗口 PID / 句柄 / frame、滚动条句柄 / 角色 / frame。模型答复、HTTP 成功或旧 AX 句柄都不能构成后验。

## 有界性与结果

- 歧义选条最多 4 轮、2 次可逆滚动写入、24 秒，并受命令级视觉预算约束；首写未落实时重新观察，不沿用旧候选。普通最新读取须由新鲜 AX 滚动条值到达底部证明，随后重新解析消息。
- 回溯在选条后至多进行 12 次滚动（含首轮），后续写入只复用已验证句柄并在每次写入和回到底部前重新检查授权、窗口、活动会话、候选角色与原始 frame；超过命令级预算则停止。加载不到请求条数时沿既有部分历史语义返回，绝不让模型补造消息。
- 当前命令之外的 watcher 和自动轮询不进入视觉轮次。协议方法、参数、结果、错误码、MQTT topic / 事件、发送与 checkpoint 均不改变；视觉失败走既有错误结构，不重投命令。
- 本批只针对滚动条歧义；`message.history` 普通路径的间歇性客户端 AX 可用性另由活体门报告记录，不用 fake 测试宣称已解决。

## 验收

Fake AX 与合成图证明：首个 AX 滚动写入丢失后重新观察并落实；回溯继续写入和恢复底部只操作选中条；推理期间策略撤销、活动会话或窗口变化时零写入；首写后策略撤销时无下一次写入；唯一 AX 路径零截图、零模型调用；最终最新位置必须由 AX 读回。真实客户端和 MQTT 只读验收由门报告单列，未自然触发歧义时标注模型分支待活体。
