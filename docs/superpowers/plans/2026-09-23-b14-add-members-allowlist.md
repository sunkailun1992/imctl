# B14 Implementation Plan — `group.addMembers` + allowlist completion (types / edits / allowAll)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** add members to an existing group through the client's 添加群成员 sheet (`group.addMembers`, dryRun, probe, console entry) and complete the send allowlist (`allowAll` switch, type toggles, entry editing, chatId / externalUserId lists) — spec `docs/superpowers/specs/2026-09-23-b14-add-members-allowlist-design.md`.

**Architecture:** the sheet is the same widget family as B7's 发起群聊 picker (`GroupPickerSheet`): generalise the locator (confirm title `确定`, sheet title text, `disabled` rows), extract the member-selection loop from `createGroup` into a shared helper, add `WeComActions.addGroupMembers` reached through the normal executor pipeline (idempotency / TTL / pause / limiter / checkpoint before `确定`). `allowAll` is one `SendPolicy` field consulted first in `ActionPolicy.allows`; the console drives every policy edit through the local CLI as today.

**Tech Stack:** Swift 6.3.3 / Swift 5 mode, SwiftPM, swift-testing, `FakeAXBackend` fixtures, swift-argument-parser, SwiftUI console.
