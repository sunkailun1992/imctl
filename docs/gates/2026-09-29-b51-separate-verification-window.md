## 根因（B50 活体后取证）

B50 build 230 上用户授权的真实 `contact.add`（键 `b50-contact-add-self-20260929-1`）按下结果行「添加」后，客户端另开**第三个 AXStandardWindow**「发送验证申请」（360×403，窗口列表中排第一）：4 段静态文本、3 张图、1 个可写 `AXTextField`（预填验证语）及其清除按钮、标题为「发送」的按钮、1 个 `AXCloseButton`，无多行文本区与列表。命令只认面板内邀请或主窗弹层，看到三个窗口即停止，结果 `unknown`，未按「发送」；用户随后手动点了发送。该命令保持 `unknown`，只按原幂等键对账（`command.get` 仍为 `unknown`），不换键重跑。

## 实现

提交 `8a7ec3e`（独立窗口）：

- 形状（只认实录）：`AddCustomerPanel.isVerificationWindow` = `AXStandardWindow`；恰一个可写单行 `AXTextField`；恰一个确认类按钮，且标题正是「发送」、可按；恰一个关闭按钮；无「添加客户」标题；无多行文本区 / 表格 / 大纲 / 列表。聊天窗（输入框是 `AXTextArea`，旁有消息列表）、只有「确定」的提示框、两个确认、两个输入框等近似窗口一律不算。面板定位与唯一面板判定跳过这种窗口（客户端把新窗口排在最前）。
- 归属：结果行「添加」按下前最后一刻，依次记企微窗口号（仅视觉命令）→ AX 窗口句柄；随后再核「没有任何窗口提供确认」且「窗口集合仍是快照」，任一不符即停在按下之前。按下后只把在窗口列表中、不在快照里、形状相符、且确认按钮在其内部的那一个窗口认作本命令的邀请窗口（`inviteWindow: "separate"`）。
- 放行：动作层 `commandOwnedPanel(inviteWindow:)` 与处理器 `freshPanel(tolerating:)` / `gate(tolerating:)` 只放过这一个已记录句柄且仍是该形状；其它多出的窗口仍按「窗口变了」停止。步骤闸门把当前面板交给处理器。
- 证据：「发送」前另有 checkpoint（共两个不可逆点）；按下后该窗口须从窗口列表消失才算 `requested`，仍开着（任何形状）为 `confirm-pressed` / `inviteDialog: still open`（执行器记 `unknown`）。
- 截图：`identifyInviteWindow` 只在按前快照含 B50 证实的主窗号时，等待并取按下后新出现、在屏、层级 0、与邀请窗口同面积的唯一窗口号；处理器截邀请窗口必须带这个号，证实不了直接拒绝（不回退几何匹配），不按「发送」。处理器新增测试缝 `contactAddRunnerFactory`（把处理器自己的截图闭包交给测试运行器）与 `windowCapture`（截图函数，默认 `WeComScreenCapture.capture`）。
- `AXApp.byBundleID`：LaunchServices 偶发报「未运行」（9/28 15:54、9/29 00:28 两次），先补查工作区列表；两处都只取未终止、pid > 0 的实例；非主线程再隔 0.1 s 查两次，主线程不睡眠。
