# 控制台会话附件与头像（2026-09-23）

## 触发与定位

用户截图显示文件、视频只给签名链接，最近的附件行出现 `message.media failed`，会话没有头像。只读活体核对：一条近期外发 PDF 回 `MEDIA_NOT_FOUND`，原因是企微 `Caches/Files` 没有这一份副本；事件能关联到同会话的一次成功 `message.sendFile`，命令记录保有原始 `url`。另一条图片行的观察窗口和相邻时间标签内都没有可匹配的缓存，且没有可靠的原始来源。控制台 `rpc(log:false)` 不更新 `lastError`，所以原先只显示笼统错误。当前 AX 树的会话行有 `AXImage` 元素，但本机探针未得到图像像素或可稳定下载的头像地址。

## 修改

- `message.media` 对缓存缺失的外发文件只使用事件里的 `commandId` 找回成功发送的原始来源；会话、外发方向、名称、大小、时间均需符合记录，下载后复核类型和字节数。结果标明 `matchedBy:sent-source`。视频若缺少本地正片缓存，按同一关联方式尝试补齐原始正片；失败保留封面。
- 控制台保留媒体 RPC 的实际错误码与原因，单次取回超时覆盖守护进程最长 300 秒上传。签名链接仅从本机配置的 OSS bucket HTTPS 主机下载，逐跳检查重定向、大小和文件头，存到应用私有目录后交给 macOS 默认应用打开。视频优先使用 `bodyUrl`，没有正文时明确说明需先在企微播放。
- 会话列表和消息行补上稳定的身份占位头像。当前 AX 和协议没有真人头像像素或可靠的名字到头像缓存映射，因此不拿相近缓存图冒充真实联系人头像。
