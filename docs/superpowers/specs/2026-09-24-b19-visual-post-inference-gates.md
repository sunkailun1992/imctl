# B19：单步视觉候选在模型返回后的命令门禁

## 背景与本批范围

B17 的单步 `AIPlannerRoundSelector` 在截图和模型调用前检查本机整窗设置、企微窗口和 AX 候选；`WeComActions.visualChoice` 在模型返回后核对候选角色、动作和几何。B18 的 `conversation.read` 可逆循环另有模型返回后的设置、暂停、策略和目标复核。其余 B17 单步视觉后备尚未统一获得这层复核：云端请求期间本机整窗许可、提供商或密钥、暂停、策略或目标改变，旧模型选择不得继续驱动客户端。

B19 先封闭这段等待与 AX 操作之间的授权间隙，不改 MQTT / MCP 方法、参数、结果、事件或错误码，不新增自由文本任务、权限、按键、坐标点击或截图范围。本批不把所有桌面命令升级为多轮 AI 执行。普通 AX 唯一路径继续直接执行，既有 B18 可逆循环继续按自身门禁运行。

## 单步视觉步骤的安全契约

1. 入口仍须是当前显式固定桌面命令；执行器原有参数、过期、暂停、目标、身份、策略、限速、幂等与 checkpoint 检查先行。后台 watcher、自动轮询和媒体方向识别不进入云端路径。
2. 截图前核对屏幕录制授权、`cloudEnabled`、`fullWindowEnabled`、所选提供商 / 模型 / 密钥以及企微 PID、单个窗口与方法目标。截图只在内存中发送至已选官方端点；不保存、不写日志、协议或事件。
3. 模型只能选择本方法、本步骤列出的新鲜 AX 候选 ID 与允许动作；模型返回后先重读本机视觉设置。整窗许可关闭、云端开关关闭、提供商 / 模型 / 密钥变化、配置不可读、超时，均丢弃旧建议。不得为同一画面自动换提供商或重试。
4. 在动作真正写入 AX 的最后可行边界，再核对当前命令来源与方法、暂停状态、当前策略、目标身份桥、活动会话、企微 PID / 窗口、候选句柄 / 角色 / 动作 / frame。目标同名、目标漂移或候选不唯一时停止；不能仅凭模型给出的文字或画面坐标补足身份。授权复核要覆盖 `visualChoice` 返回到调用方执行 AX 之间可能发生的等待；若该调用方会延后写入，应在写入前再运行门禁。
5. 对可逆操作，写入后用新的 AX 状态判断该方法后验；模型的 `verify` 或 HTTP 成功不构成客户端证据。对不可逆操作，仍由原 `CommandExecutor` 路径在实际提交前 checkpoint；推理后门禁失败时不提交，已提交而证据不足维持 `unknown`、同幂等键不再次执行。`broadcast.confirm` 仍必须由精确 `msgid` 与唯一发送按钮证明任务关联。
6. 门禁应靠近每次 AX 变更，避免把旧 `ActionPolicy` 快照视为当前政策。它不是 macOS UI 的原子事务；动作后的客户端证据与不确定终态仍不可省略。

## 覆盖与非目标

本批核对现有单步视觉调用点：会话选行、历史滚动条、发送按钮、联系人申请卡片与添加联系人按钮、群名称输入框、建群确认和添加群成员入口。逐个把动作种类映射回原 `ActionKind` 与原目标；不能以一个泛化的“视觉允许”布尔值代替各方法策略。原有唯一 AX 快速路径不因新增检查而触发全窗上传。

后续逐阶段扩展 B17 所列桌面命令的有界多轮执行：先处理 `message.history` 的可逆滚动与最新位置，再抽取发送 / 发文件 / 改群 / 加群成员共用的目标选中阶段，最后为联系人、群和广播各自定义可观察步骤与不可逆提交边界。`account.status`、`conversation.list`、`contact.list` 等 AX 足够的只读方法应保留零模型成本；`client.navigate` 不借整窗许可扩大到未验证窗口或菜单。每一阶段仍需独立 fake、真实客户端和 MQTT 门报告。B19 完成不能宣称所有命令已有 Codex 式规划或全部活体验收。

## 验收条件

- Fake 模型在推理期间触发整窗许可 / 云端开关关闭、提供商 / 模型 / 密钥替换、暂停、策略撤销、目标身份变化和窗口 / AX 候选变化时，旧建议之后 AX 写入计数为零；对不可逆路径还须证明提交计数为零。配置不可读或候选含糊也失败关闭。
- 模型 `reobserve`、`stop`、超预算、伪造候选与越权动作不越过方法门禁；原 AX 唯一读路径零截图、零请求。B18 循环、后台 watcher 与协议 / MQTT 对账回归通过。
- 使用合成图、fake AX 与 fake 模型验证；活体优先显式只读步骤。写入仅在获准的本人测试目标、明确条数内进行，写入数量和客户端证据记录于 B19 门报告。未触发的真实模型分支标待活体，不以单测代替。
