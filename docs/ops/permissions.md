# 权限：一次性授权与检查

imctl 的会话读取和控制以辅助功能为准。B15 对方向未知的可见图片行按需截企微单帧，只在本机判向，不上传。B16 仅在「添加群成员」按钮歧义时上传按钮裁图。B17 对**显式固定桌面命令**提供独立的整窗辅助开关。B34 在该开关开启且目标未活动时，为 `conversation.read` 和四个写命令的选目标前缀主动上传经核验的企微主窗截图，并在动作后上传新鲜截图复核。B35 把同样受控的两轮观察扩展到显式读取前确实需要的单滚动条回最新、唯一「新的客户」行选中。B36 将两轮被动观察扩展到直接调用的文本与附件发送之唯一输入框暂存阶段；视觉模型不负责提交。其它步骤仍用各自的 AX 或受限视觉后备。后台 watcher、自动申请和 B15 判向不使用这个开关。安装检查仍为六项。权限以**守护进程 `imctld` 自己**的读回为准（TCC 按进程 / 签名身份记，终端里 `imctl permission` 的结果不代表守护进程）：

| 授权 | 用途 | 谁来给 | 怎么持久 |
|---|---|---|---|
| 辅助功能 | 读写企微界面（AX 树、pid 级回车） | 系统对话框（守护进程在 launchd 下自动弹）或 系统设置 › 隐私与安全性 › 辅助功能 勾选 imctld | 签名身份不变就一直有效 |
| 屏幕录制 | B15 本机图片方向；B16 显式操作的按钮裁图；B17/B34/B35/B36 在另行启用整窗辅助后，为限定的显式固定桌面步骤截取企微主窗。后台观察和自动申请不上传 | 系统对话框或 系统设置 › 隐私与安全性 › 屏幕录制 允许 imctl.app 对应的守护进程 | 签名身份不变通常可沿用；macOS 要求时重启应用及守护进程 |
| 访问其他 App 的数据 | 图片来自企微容器 `~/Library/Containers/com.tencent.WeWorkMac`（`message.media`） | 第一次访问时的系统对话框「“imctl.app”想访问其他App的数据」 | 2026-09-16 观察：重装新版本有时会**再弹一次**（build 61 弹、60 / 62 没弹） |
| 完全磁盘访问权限 | 覆盖上一项，且更新后不再弹窗 | 只能手动：系统设置 › 隐私与安全性 › 完全磁盘访问权限 › 加 `imctl.app` | 签名身份不变就一直有效 |

控制台体检页的「界面诊断」在控制台进程内读客户端时另需勾选 `imctl 控制台` 的辅助功能（可选）。屏幕录制判断由守护进程执行，控制台只显示其授权状态。

## B16 云端视觉开关（应用设置，不是 macOS 新权限）

默认提供商是千问；本机可选择 Gemini 等已支持视觉输入的模型，并单独保存每家密钥。**屏幕录制显示 `granted`、B16 云端视觉已启用，都不代表整窗辅助已授权。**完整企微窗口可能包含其它会话预览和聊天内容。B17 必须再从控制台「设置 → 视觉识别」点「允许整窗辅助」，或执行 `imctl vision full-window --enable`；`imctl vision status --json` 的 `fullWindowEnabled` 可读回。旧配置缺少此字段时默认关闭，第二台 Mac 须单独开启。禁用用 `imctl vision full-window --disable`；关闭云端视觉或删除当前提供商密钥也会关闭整窗辅助。密钥、截图和模型原文不进入日志、MQTT 或安装包。提供商侧处理与留存取决于其服务条款。

B34 不增加新的 macOS 授权项。在 `fullWindowEnabled` 为 true 且目标未活动时，显式 `conversation.read` 和 `message.send`、`message.sendFile`、`group.rename`、`group.addMembers` 的选目标步骤即使已有唯一 AX 行，也会由视觉模型选择候选；AX 动作后再用新鲜企微主窗截图作模型复核，最后以 AX 活动标题严格核验。只读会话可选择窗口可见但 AX 标题缺失的可操作行；写命令的候选必须有与目标严格一致的 AX 标题。模型不能选择只有像素位置而没有 AX 动作的控件，不能控制发送内容或提交动作。目标已经活动时不为选目标上传；除下述 B35 两步外，未列入 B34 的方法保持各自的 AX 或受限视觉后备。`setup --check` 六项通过并不能证明模型已被调用；`controller.describe` 的 `visionCaptureCount`、`visionRequestCount`、`visionHTTP200Count` 是进程级数值累计，可读前后差分，HTTP 200 不等于有效模型决策或命令成功。命令响应不携带图片或模型原文。

B35 不增加 macOS 授权项。整窗视觉已启用的显式普通 `message.history` 只有在需要回最新、且消息区仅有一个可见可写竖向 AX 滚动条时，才主动执行滚动前截图模型选择与滚动后新截图模型复核，最后由 AX 值证明到底。显式 `contact.request.list`（以及 `contact.request.accept` 共用的读取导航）只在「新的客户」行未选中、左侧唯一可见行的 AX 文本精确匹配时主动进行选行前后两轮；最终须读回 AX 选中行和申请表就绪。已到底、已选中且表就绪、整窗关闭时不为这些步骤上传，沿原 AX 路径；接受动作仍由原 AX 流程执行。`message.history` 与 `contact.request.list` 两条只读分支已有真实千问两轮、AX 后验和 MQTT 成功读回，见 B35 门报告；接受申请的提交没有活体写入验收。`setup --check` 或配置就绪本身不证明模型参加某次命令。

B36 也不增加 macOS 授权项。直接调用的 `message.send` / `message.sendFile` 只有在唯一可写聊天输入框、活动目标和原有发送准入已由 AX 证明，且整窗视觉开关与屏幕录制均就绪时，才在固定正文或附件暂存**之前和之后**各上传一帧经核验的企微主窗；模型只复核这一准备阶段。暂存后由 AX 精确值或单个原生附件对象守卫确认，原 checkpoint、Return 和新外发消息证据仍负责提交与终态。群发子命令不触发此 B36 观察；模型停下或画面漂移时不退回纯 AX 继续发送。B36 真实视觉发送仍待活体门报告，不得用已有纯 AX 发送验收替代。

## 一次性初始化

```bash
~/Applications/imctl.app/Contents/MacOS/imctl setup
```

1. 装好 / 重启 LaunchAgent；2. 让守护进程请求辅助功能、屏幕录制与「访问其他 App 的数据」（`controller.permissions{prompt:true}`）；3. 如屏幕录制尚未允许，打开对应的系统设置页；完全磁盘访问权限需手动添加；4. 等系统授权完成后复查。控制台「体检」页与初始化向导的「安装并请求授权」做同样的事，屏幕录制与完全磁盘访问权限各有「打开系统设置」按钮；如 macOS 提示，重启应用及守护进程后再检查。

也可以只用控制台：首次打开会弹出初始化向导，第 1 步「安装与授权」的按钮先确认再执行；之后在「体检」页逐项点按钮（打开系统设置、重启守护进程等都会先确认）。

## 换签名证书或新 Mac 后授权不生效（2026-10-11 实录）

- 换了签名证书后（例如在新 Mac 上新建证书），系统设置里原来的条目开关仍亮着，但授权库记的还是旧证书，对新版本无效，`setup --check` 仍是 ✘。处理办法：在三个列表里删掉旧条目（「−」）再加；或者由用户自己在终端执行 `tccutil reset All com.sunkailun.imctl.console` 一次清掉，再运行 `imctl setup`。
- 清掉之后：
  - 辅助功能会弹系统对话框；
  - 屏幕录制可能既不弹框、列表里也没有条目，「+」里也选不到 `~/Applications/imctl.app`。从访达把 `imctl.app` 拖进「屏幕与系统录音」列表就可以；
  - 完全磁盘访问权限的条目会出现但开关是关的，打开即可。
- 列表里的条目显示为「imctl 控制台」：守护进程 `imctld` 在这个 app 里面，用的就是它的授权。
- 屏幕录制打开后，重启守护进程（`launchctl kickstart -k gui/$(id -u)/com.sunkailun.imctl`），再运行 `imctl setup --check`；体检（`imctl doctor`）的修复提示也写了这几步。

## 检查

```bash
~/Applications/imctl.app/Contents/MacOS/imctl setup --check
```

授权之外各功能能不能用（企微可读性、策略、视觉、MQTT、OSS、智能体接入）用 `imctl doctor` 看。

或控制台 ›「体检」页（打开时只做本机检查，不联网），或任何客户端调 `controller.permissions`（不传 `prompt` 不弹框）。读回包含 `screenRecording: granted|denied`；`setup --check` 显示六项，缺辅助功能、屏幕录制、企微数据访问或守护进程条件时退出码为 2。「完全磁盘访问权限」可选，但建议授予以免更新后重复弹窗。

「完全磁盘访问权限」一行是守护进程自己试读 TCC 数据库得出的（只有持有该权限的进程能打开）：先试 `~/Library/Application Support/com.apple.TCC/TCC.db`，再试 `/Library/Application Support/com.apple.TCC/TCC.db`。**macOS 27.0（2026-09-22 观察）已没有用户级那份**，1.0.0 只读用户级，所以在 27.0 上永远报 `no`、并因此跳过企微数据探测——那是探测的假阴性，不是授权丢了；1.0.1 起回退到系统级库。判据：`controller.permissions{probe:true}` 返回 `wecomData: granted` 且不弹框，就是授权在。

macOS 27.0 上系统 TCC 库里的条目按 bundle 记（`com.sunkailun.imctl.console`），同时覆盖包内的 `imctld`；在系统设置里切换该权限后若探测仍不到，重启一次守护进程：`launchctl kickstart -k gui/$(id -u)/com.sunkailun.imctl`（是否必需未单独验证）。

## 更新后再弹窗怎么办

点「允许」即可；不想再遇到就把 `imctl.app` 加进完全磁盘访问权限。守护进程侧任何被对话框挡住的文件访问 8 s 后返回可重试的 `MEDIA_NOT_FOUND`，不会拖住其它命令。

## 剪贴板（B13 `message.sendFile`）

发文件时守护进程会：快照你当前的剪贴板 → 放入 outbox 文件的 URL → 在 ⌘V 前核对剪贴板仍是这个文件 → 对企微投一次 ⌘V（用户 2026-09-22 17:43 批准的唯一新按键）→ 确认输入框出现附件。若剪贴板仍是本次文件 URL，就恢复原快照；若你在此期间复制了新内容，就停止尚未执行的粘贴并保留你的新剪贴板内容。剪贴板不需要额外授权。outbox 在 `~/Library/Application Support/imctl/outbox/`（0700），文件发完即删；守护进程启动时再清一次（`FileFetcher.sweep`）：删掉超过 1 小时的下载目录，以及旧布局遗留的散文件，1 小时内的目录留着，免得清掉还在途的发送。

添加群成员不需要新权限（同一辅助功能；回车沿用选人面板搜索框已批准的那次）。
