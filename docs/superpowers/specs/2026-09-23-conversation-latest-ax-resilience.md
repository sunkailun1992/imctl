# 会话最新消息与辅助功能读取容错规格（2026-09-23）

## 背景与用户决定

build 141 的真实控制台截图表明：已选会话的图片方向仍可能无法确认；普通「读 30 条」会遇到 `-25201` 的 `AXValue` 读取错误并清空消息区；当企微自己停在历史位置时，只把 imctl 列表滚到底部并不能加载企微最新消息。用户要求普通读取默认展示最新内容，并在 imctl 聊天区定位最下方。

沿用既有决定：控制台用于检查，MQTT 是主要数据通道；附件只按需取地址，不恢复图片或视频自动预览；守护进程的观察轮次不得主动滚动或切换企微会话。后续用户进一步确认「文件传输助手」的消息都属于当前账号，因此该会话在 `message.history` 与 MQTT 观察事件中统一为 `outbound`；其它会话仍按 AX 证据判断方向。

## 行为契约

1. 显式 `message.history{scrollback:false}` 先把**当前已打开**的企微消息区定位底部，再解析并返回最后 `limit` 条消息。该动作不打开其他会话，不由 watcher 自动调用；不能证明已到最新位置时明确报错，不把旧页冒充最新。
2. `scrollback:true` 保持主动读取更早历史的语义，读后恢复企微消息区位置；控制台不因此强制跳到 imctl 列表底部。
3. 控制台普通读取成功后滚到最后一条。会话切换或新请求开始后，旧异步结果不得覆盖当前会话；读取失败时显示错误，不把上一会话的内容当作当前会话。
4. 单条消息的暂时性 `AXValue -25201` 只在该属性上重试一次。仍不可读时显式标为不完整；不以空文本或缺失几何伪造媒体、方向或稳定消息键，不以该行触发 `message.observed`。布局整体不可达及其他 AX 错误继续失败。
5. 除精确匹配「文件传输助手」这个自我会话外，方向只凭同一气泡几何或独立发送者标签等可核对的 AX 证据推断。普通私聊无锚点的媒体保持 `unknown`，MQTT 不根据其它会话标题猜方向。

## 验收

- Fake AX 覆盖停在旧页、定位最新、无滚动能力、回滚、`-25201` 一次恢复与持续失败、其他错误不降级、群发送者标签正反例。
- 控制台模型测试覆盖普通加载底部、回滚保位、会话切换时过期结果丢弃与错误显示。
- `swift build`、完整 `swift test`、secret 扫描通过；本机只读回读记录条数、错误类别和耗时，不记录真实正文或签名地址。
- 制品、签名、本机守护进程、MQTT 与第二台 Mac 包分别取证；真人 GUI 位置和偶发 AX 失败复现未实测时明确标待验。
