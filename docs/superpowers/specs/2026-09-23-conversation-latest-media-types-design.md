# 会话最新定位与媒体类型（2026-09-23）

## 背景

控制台打开会话后会停在消息列表顶部；无文本媒体行统一写成“图片 / 表情 / 卡片”，而业务侧通过 MQTT 收到的观察事件也缺少可判断为图片的字段。企业微信 AX 在部分行上没有图片元素或发送方向锚点，不能用气泡尺寸猜测图片和方向。打开活动会话虽已跳过重复 `conversation.read`，切换会话仍有重复消息解析。

## 目标与边界

- 普通 `message.history` 完成后，控制台定位到返回的最后一条；显式回滚历史保留用户的位置。
- 控制台把 PDF / Word 等文件、视频和有证据的图片分别显示；没有证据的无文本行写“未识别媒体”，未知方向写“方向未确认”。附件维持手动获取签名地址，不自动下载或播放。
- `message.history` 与 MQTT `message.observed` 保持 `kind` 兼容，为 `kind=media` 增加 `mediaType=image|unknown`。仅当活动会话的选中列表行最新预览明确为 `[图片]` 且最后一条消息行是无文本媒体时，才给 `image`；其它行给 `unknown`。
- `conversation.read` 的消息数量和会话类型共用一次解析；原策略、目标复核与返回字段不变。

## 验收

- fake AX 测试覆盖图片证据、旧媒体未知、预览/活动标题不符、文件与视频不带 `mediaType`，以及历史和 watcher 事件一致。
- MQTT 事件泵测试覆盖 `mediaType` 透传；控制台测试覆盖类型标签及默认/回滚的滚动请求。
- 全量构建和测试通过，门报告单独说明真实 AX 耗时、真人界面与 MQTT 活体验收边界；不发送消息。
