# 跨日消息键与附件缓存对应修复（2026-09-24）

## 条件与故障证据

- 用户在 build 151 的测试私聊看到一条图片消息，但控制台提示“企微本机没有这份附件缓存”，该行方向为“方向未确认”。本批没有发送消息或更改策略。
- 只读 `message.history` 能返回该会话的 3 条消息行，图片行有 `messageKey`；显式 `message.media` 返回 `MEDIA_NOT_FOUND`，内部原因是相邻时间标签区间内有 1 条媒体行、却有 0 个**未占用**的候选文件。
- 当前企微档案的图片缓存中确实存在 1 个签名为 JPEG、日期和该行匹配的文件；它被上一日同一消息的旧键占用。旧键使用“HH:mm”，当日界面改为“昨天 HH:mm”后，新键不同。因而原控制台文案把“找不到可确认的对应关系”误说成“本机没有文件”。这里只核对元数据、文件头、键计算和匹配分支；没有复制私人图片内容到仓库。
- 企微辅助功能树中的这条图片行只有时间文字，没有可辨的头像或图片侧边锚点。用户截图中的左右位置不能作为守护进程可读的 AX 证据；本批保持 `direction:unknown`，不向 MQTT 猜测入站或外发。

## 实现范围

- `message.history` 与观察者共用的消息键把可解析的企微时间标签转成绝对 UTC 分钟后哈希；原始标签仍返回给控制台和 MQTT。跨日从“HH:mm”改为“昨天 HH:mm”时，同一消息继续得到同一键。
- 对已按旧键占用的图片缓存，考虑当前原始时间标签以及明确的“昨天 HH:mm”旧裸时钟标签；只在当前会话里该行、唯一旧键和缓存文件能对应，且文件签名、修改日期均符合时迁移分配及已有观察记录。歧义或不匹配继续返回 `MEDIA_NOT_FOUND`。不靠相近时间借用另一条消息的文件。
- 控制台的 `MEDIA_NOT_FOUND` 文案改为描述对应关系无法确认，并提示可在企微打开原附件后再试；不把它等同于本机没有缓存。
- 协议文档同步消息键口径和旧键迁移边界。图片仍按需取签名地址，控制台不自动渲染或下载；没有增加录屏、发送、策略或 MQTT 字段。

## 边界

- 历史 raw-label 消息键在升级到规范化键时有一次性变化；消费方不得仅凭键变化触发重复发送。守护进程的历史差分不以键作为新增判据。
- 没有可靠 AX 方向锚点的图片行继续为 `unknown`；`MEDIA_NOT_FOUND` 也可能表示文件确实已被企微清理，打开原图后重试只对能够重新落地缓存的消息有效。
