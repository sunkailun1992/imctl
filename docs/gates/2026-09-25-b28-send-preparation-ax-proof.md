## 范围与结论

`message.send` / `message.sendFile` 的目标选中继续使用 B20；本批只收紧聊天输入框选择、正文/附件暂存到不可逆提交之前的证据。AX 无法独立证明多编辑框的语义或暂存附件的文件身份，因此没有开放新的模型 `writeText`、`press`、`⌘V` 或提交轮次。底部双编辑框明确失败，正常唯一输入框零截图。协议、白名单、策略、checkpoint 与批准按键清单不变。

## 代码与假件

| 核对点 | 结果 |
|---|---|
| 编辑框 | 只选消息视口下方、窗口内且会话表右侧的唯一可写 `AXTextArea`；外部大编辑框无法抢占，双底部编辑框在暂存前失败。 |
| 文本 | 设值读回后提交前再核同一活动会话、句柄与调用方原文；用户改动保留，零 Return。失败只清本次仍可确认的草稿。 |
| 文件 | 粘贴期间出现文本草稿即阻断 Return 并恢复剪贴板；没有暂存信号或提交前信号/目标变化均停止。信号仍不能证明文件身份。 |
| 提交后读 | 消息表 AX 读取失败不逃逸成 `CLIENT_UNAVAILABLE` 的可重发失败，记录 `unknown`。 |
