# B53：初始化向导、体检页与快捷修复（引导 B 期）

## 背景与目标

B52 交付了体检：`controller.readiness`、`imctl doctor`，以及控制台状态页里的面板。它能说清每项卡在哪、给出可复制的修复命令，但用户还得自己去终端粘贴命令；授权、界面诊断等检查也散在控制台各处。

本批要做到：
- 拿到安装包的人打开控制台，就能被一步步带着完成初始化；
- 平时有一个体检页集中看所有检查，每个问题点一下按钮、确认后就修；
- 只用终端的人，用 `imctl doctor --fix` 能做到同样的事。

## 用户决定（2026-10-12）

- 形态：分步向导加体检页。
  - 第一次打开控制台且体检未就绪时，自动弹出向导；走完或关掉都记住。
  - 之后未就绪时，控制台打开就停在体检页；体检页和菜单栏都能重新运行向导。
- 向导步骤：必需步骤（安装与授权 → 企业微信 → 发送范围）后，勾选要用的功能，只展开勾选的那几项，最后跑一次完整体检。
- 每项体检都配快捷按钮。**会执行操作的按钮一律先确认**；跳到设置页或策略页只是换个页面，不弹确认。
- 新增体检项四组：安装一致性、界面诊断并入、运行健康、对接状态（只提示）。控制台里分散的检查都合进体检页。
- 命令行加 `imctl doctor --fix`，与控制台用同一套动作。
- 做法：动作由守护进程写在体检结果里，用类型表示，控制台和命令行各自执行。**任何客户端都不执行报告里的命令文字**（沿用 2026-10-12 的原则）。

## 动作（协议）

`ReadinessFix` 在 `text`、`command` 之外，新增可选的 `action: {kind, target?}`。客户端碰到不认识的 `kind`，只显示文字，不给按钮。

| `kind` | `target` | 做什么 | 控制台 | `doctor --fix` |
|---|---|---|---|---|
| `openSystemSettings` | `accessibility` / `screenRecording` / `fullDiskAccess` | 打开系统设置对应页（写死的三个地址） | 确认后打开 | 确认后打开 |
| `openWeCom` | — | 打开企业微信 | 确认后打开 | 确认后打开 |
| `setup` | — | 安装或更新常驻，并请求授权 | ★ | ★ |
| `reinstallDaemon` | — | 按当前配置重装常驻（有 `mqtt.json` 就带 `--mqtt`） | ★ | ★ |
| `restartDaemon` | — | 重启守护进程 | ★ | ★ |
| `resumeDaemon` | — | 解除手动（api）暂停 | 确认后执行 | 确认后执行 |
| `registerAgents` | — | 在 Claude Code、Codex 注册并安装技能 | 确认后执行 | 确认后执行 |
| `installSkills` | — | 更新两边的技能文件 | 确认后执行 | 确认后执行 |
| `retest` | — | 重新联网实测（含一次模型调用） | 确认后执行 | 确认后执行 |
| `openSettings` | `mqtt` / `oss` / `proxy` / `vision` | 跳到设置页对应标签 | 只换页 | 打印 `command`，不执行 |
| `openPolicy` | `phones` / `autoAccept` / `allowlist` | 跳到策略页 | 只换页 | 打印 `command`，不执行 |
| `openLogs` | — | 看日志 | 只换页 | 打印日志位置 |

- ★ 表示会重启守护进程。执行前先读一次 `runningCommands`（新事实，见下），大于 0 就拒绝，并说明「有命令正在执行，稍后再试」；等于 0 才弹确认框，写明「守护进程会重启，几秒内不可用」。守护进程没在运行时不用检查。
- 确认框和命令行提问的文字由客户端按 `kind` 生成；守护进程只发类型。
- 每条修复建议对应哪个动作，在 `ReadinessEvaluator` 里与修复文字一起写定，实施计划给出逐条对照表。原则：
  - 授权缺失：辅助功能用 `setup`（提示框会创建授权条目），其余用 `openSystemSettings`；
  - 配置缺失或无效：用 `openSettings` / `openPolicy`；
  - 「重启后生效」：用 `restartDaemon`；没有以 MQTT 模式运行：用 `reinstallDaemon`；
  - 手动暂停：用 `resumeDaemon`；联网实测失败：配置类问题用 `openSettings`，其余用 `retest`；
  - 没有可行动作的（例如企业微信版本未校准、通讯录布局未适配），不带 `action`。
- 智能体（MCP）也能看到 `action`。SKILL.md 不变：只报告，不执行。
- 协议 §6.45 同步更新（`fix.action` 字段与类型表）。

## 新增体检项

守护进程报告里新增的事实只有计数、build 号和时间，不含命令内容、会话名或路径：
- `runningBuild`：守护进程启动时读到的自身 `CFBundleVersion`；
- `installedBuild`：体检时读磁盘上同一个 app 的 `CFBundleVersion`；
- `runningCommands`；
- `failedLastHour`、`unknownLastHour`：最近一小时内结束为失败或结果未知的命令数；
- `watchErrors`：watcher 启动以来轮询出错次数；
- `lastMQTTCommandMs`：最近一次经 MQTT 收到命令的时间。

不在 app 包里运行时（例如开发构建直接跑 `imctld`），两个 build 号都为空，安装一致性不判定。

| 组 | 检查 | 判定 | 动作 |
|---|---|---|---|
| 安装一致性 | `runningBuild` 与 `installedBuild` 一致 | 不一致：`daemon` 为 `fail`（升级后没重启） | `restartDaemon` |
| | 控制台 / 命令行自己的 build 号与 `runningBuild` 一致（客户端比对） | 不一致：提醒（可能开的是另一份 app） | 守护进程较旧时给 `restartDaemon` |
| 界面诊断 | 控制台自己的辅助功能（控制台进程判断） | 未授权：本机客户端组 `fail`，只影响界面诊断，不影响就绪 | `openSystemSettings(accessibility)` |
| | 会话表、消息表、输入框能否读到（原「诊断」页，点「诊断界面」时在控制台进程只读一次） | 读不到就列出原因 | — |
| 运行健康 | `failedLastHour`、`unknownLastHour`、`watchErrors` | 新的可选能力 `health`，只出提醒，不影响就绪 | `openLogs` |
| | 通讯录角标能否归属（watcher 每轮的读数） | 自动接受开着、角标却归属不了：`autoAccept` 为 `fail` | 无（布局适配另开批次） |
| 对接状态（只提示） | `lastMQTTCommandMs` | MQTT 模式下显示「最近一次收到命令」 | — |
| | 终端里能否直接打 `imctl`（客户端判断） | 只显示，附可复制的链接命令（要 sudo，由用户决定） | — |

「控制台自己的辅助功能」「与守护进程同版本」「终端能否直接打 imctl」只有客户端知道，所以在体检页单列一组「本机客户端」，不进守护进程的报告。命令行 `doctor` 显示后两项。

## 控制台：体检页

- **侧栏**：「概览」下最上面新增「体检」；「监控」里的「诊断」并入体检页的「界面诊断」，侧栏去掉这一项。
- **体检页**：
  - 顶部：结论与下一步（带按钮）、联网实测时间、「运行体检」「重新实测」（后者就是 `retest` 动作，要确认）、「只做本机检查」、「重新运行向导」；
  - 中间逐项列出能力：每条检查、提醒、修复文字、动作按钮、可复制命令；
  - 下方依次是「本机客户端」组和「界面诊断」（按钮「诊断界面」，只读，不弹确认）。
- **状态页**：去掉「授权与本机」和「体检」面板，以及「常用操作」里的「检查授权」，这些都由体检页覆盖；「在程序坞显示图标」开关移到「常用操作」。概览卡片、暂停 / 恢复、运行详情、守护进程维护、原始信息保留。
- **运行时机**：
  - 打开体检页或向导时，自动跑一次只做本机检查（`online:false`，不联网、不调模型）；
  - 联网实测只在点「运行体检」或确认 `retest` 后才跑；
  - 定时刷新照旧不调用体检。
- **启动**：控制台启动后先跑一次本机检查。第一次启动且未就绪就弹向导；之后未就绪就选中体检页。
- **菜单栏**：新增「体检…」「初始化向导…」。
- **顺带修复**（B52 推迟的小问题，与本批同一处代码）：
  - 守护进程连不上或版本太旧时，体检页显示兜底信息（与 `doctor` 的兜底一致：app、常驻文件、是否加载、进程、企业微信）并给出 `setup` 按钮；
  - 只做本机检查时不显示上一轮的实测时间；
  - 命令行不再出现「未实测（未实测）」，`--offline` 的首行改为「只做了本机检查」；
  - 手动运行守护进程时，修复建议先说明要停掉手动的那个。

## 控制台：初始化向导

盖在主窗口上的分步面板。每一步「完成没有」都看本机检查的结果，不另写判定。

1. **安装与授权**：后台常驻、辅助功能、屏幕录制、访问企微数据、完全磁盘访问权限。守护进程连不上时，读兜底信息，主按钮是 `setup`。屏幕录制写明「列表里没有就从访达把 imctl.app 拖进去」。
2. **企业微信**：在运行、会话列表读得到；按钮 `openWeCom`。
3. **发送范围**：只展示当前范围（默认只有文件传输助手；allowAll 开着会醒目提醒），向导里不改策略，并提示完成后到「策略」页修改。
4. **要用哪些功能**：勾选智能体接入、MQTT、视觉兜底、OSS、企微代理，已配置的默认勾上。按手机号加人、自动接受好友申请属于策略，完成页提示到「策略」页开启。
5. **按勾选展开**，每个功能一步：
   - 智能体接入：`registerAgents`；
   - MQTT、视觉、OSS、企微代理：嵌入设置页的同一个表单。把 `SettingsView` 的四个表单拆成独立组件，设置页和向导共用。这一步只保存。
6. **应用配置**：前面保存的配置里有需要重启才生效的（MQTT 模式、OSS、企微代理、视觉按钮裁图），就在这里执行一次 `reinstallDaemon`。只确认一次，只重启一次，并遵守 ★ 的检查。不需要就跳过这一步。
7. **完成**：按钮「运行完整体检」上写明会联网实测、含一次模型调用，点它即是确认。结果显示方式与体检页相同，没过的项旁边带按钮。点「完成」关闭向导。

- **导航**：「上一步 / 跳过 / 下一步」。必需步骤也能跳过，但会提醒，完成页列出没做的。
- **检查时机**：不用定时器。每个动作执行完、控制台重新成为前台窗口（例如从系统设置切回来）、或点「重新检查」时，各跑一次本机检查。
- **标记**：控制台的 UserDefaults 里存一个「向导已完成或已关闭」的标记。体检页和菜单栏都能重新打开向导，重新打开不受标记影响。

## 命令行 `imctl doctor --fix`

- 先照常出体检报告，然后按「下一步」的顺序，逐个处理带 `action` 的 `fail` 项：先说明要做什么，再问「执行吗？[y/N]」，默认不执行。★ 动作先查 `runningCommands`，大于 0 就跳过并说明。
- `openSettings` / `openPolicy` 只打印 `command`；`openLogs` 打印日志位置。
- 只处理 `fail` 项；`disabled` 的可选项不处理，启用新功能是向导的事。
- stdin 不是终端时拒绝 `--fix`；不提供全部同意的参数。
- 处理完再跑一次本机检查并显示结果。退出码沿用 `doctor` 的 0 / 2 / 3。

## 安全与隐私

- 动作只认固定的类型表，不执行报告里的命令文字，不接受客户端传来的路径或命令。
- 不新增系统权限，不新增网络端点。系统设置只打开三个写死的地址；动作复用现有的执行路径（安装 / 重启常驻、`mcp install`、`NSWorkspace` 打开应用）。
- 会重启守护进程的动作，在有命令执行时一律拒绝；所有执行类动作都由用户点按钮并确认。安装常驻仍是用户的决定。
- 向导不改策略；密钥只在 `SecureField` 里输入，不回显，沿用现有的 0600 保存方式。
- 新增的报告事实只有计数、build 号和时间。`ForbiddenAPITests` 不放宽。

## 测试与验收

- **单测**：
  - 每条修复建议都带对的 `action`；不认识的 `kind` 能解码，只显示文字；
  - 新事实到新检查项的判定：build 不一致、运行健康提醒、角标与自动接受；
  - 守护进程：启动时记下的 build 号与磁盘值的比对、最近一小时的计数、`lastMQTTCommandMs`、`runningCommands`；
  - 控制台：执行类动作必须先确认；★ 在有命令执行时拒绝；换页类不确认；向导的状态流转（跳过、勾选展开、只在需要时进入应用步骤且只重启一次、标记写入与重新打开）；打开体检页只做本机检查；定时刷新不体检（沿用 B52 的测试）；兜底显示；
  - 命令行：`--fix` 的询问顺序、默认不执行、非终端拒绝、★ 遇到命令执行时跳过、换页类只打印。
- **变异**：执行类动作要确认、★ 遇到命令执行时拒绝、不执行命令文字、只重启一次、完成标记、build 比对、换页不确认，各删一处，都应有测试变红。
- **活体（这台 Mac）**：
  - 装新版本时先故意不重启，看体检能否抓到 build 不一致，再点按钮重启修复；
  - 退出企业微信，在向导第 2 步点「打开企业微信」恢复；
  - 向导完整走一遍，看已配置的功能是否显示 ✔；
  - 用 `doctor --fix` 修一项；
  - 体检页看界面诊断、本机客户端组和兜底显示。
- **全新环境**：「只靠控制台从安装走到就绪」需要另一台 Mac 或新建的 macOS 用户，用户决定是否做；不做就在门报告里标「待活体」。
