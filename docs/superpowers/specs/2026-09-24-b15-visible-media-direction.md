# B15：可见媒体行的方向补证据

## 背景与用户决定

企微 5.0.11 的部分私聊图片行在辅助功能树里只有时间标签，行和单元格横跨消息区；定点 AX 读取与增强模式均无左右锚点。现有 `direction:unknown` 是正确的保守结果，但控制台无法摆放气泡，MQTT 消费方也不能区分来源。用户于 2026-09-24 同意对方向未知的图片按需截取企微窗口、只在内存判断且不保存，并要求把屏幕录制权限加入「授权与本机」及本机安装。

## 范围与约束

- 只对 AX 仍无方向、且可见的无文本 `media` 行做单帧窗口截图。此类行可能是图片、表情或卡片；旧行在 AX 中不一定能进一步区分。方向判定必须保守，有双侧或居中内容、截图失败、授权缺失时保留 `unknown`。
- 显式 `message.history` 一次至多截一帧；观察者仅在同一会话新增媒体行且即将生成 `message.observed` 时截一帧。首次历史基线、会话切换、常规无变化轮询不截图。
- 截图像素不写文件、日志、数据库或协议，不上传；不对图片下载、解码或行内渲染。没有新增合成输入或客户端发送，发送条数为 0。
- `controller.permissions` 增 `screenRecording:granted|denied`，`prompt:true` 由守护进程触发系统授权；CLI `setup --check`、控制台「授权与本机」、安装说明同步。
- 结果沿用既有 `direction` / `origin` 字段：同一判断用于 `message.history` 与新媒体的 MQTT `message.observed`，无需新事件或媒体字节字段。绝不把 `unknown` 猜成对方。

## 验收

1. 合成窗口图覆盖左、右、居中、双侧、空白、小头像、缩放与视口裁切，只有单侧大块证据给方向。
2. fake AX 测试覆盖显式历史读取的范围和观察者仅对新增行补方向，事件来源同步。
3. 守卫测试仅允许审计过的权限请求与单帧截图文件触及屏幕录制 API。
4. 完整构建、测试、secret 扫描和本机安装读回；真实企微只读核对授权、速度与方向。未拿到系统授权时如实标注待活体。
