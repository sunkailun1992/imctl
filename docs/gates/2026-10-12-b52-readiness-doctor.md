## 实现

规格 `docs/superpowers/specs/2026-10-10-b52-readiness-doctor.md`，计划 `docs/superpowers/plans/2026-10-11-b52-readiness-doctor.md`，共 16 个任务，Task 16 是追加项。

- **`controller.readiness`**：分发器层面的查询，与 `event.replay` 一样不建命令记录、不发事件、不进执行器队列。
  - 共 12 项能力：必需的 `daemon`、`wecom`、`read`、`send`、`media`，以及可选的 `contactAdd`、`autoAccept`、`vision`、`mqtt`、`oss`、`agents`、`wecomApi`。每项给出 `ok / fail / disabled / unknown`、逐条检查和修复指引。`ready` 与 `nextStep` 按规格判定。
  - 联网实测在后台跑，同一时间最多一轮，总期限 40 秒；结果缓存 300 秒，`refresh` 至少间隔 60 秒，不分调用方。实测内容：
    - 视觉：程序画的合成图走一次 B16 客户端；
    - MQTT：QoS 1 发布到 `im/<id>/readiness`，等 broker 确认；
    - OSS：1 KB 往返；
    - 智能体：`imctl mcp serve` 握手，只发 `initialize` 与 `tools/list`；
    - 企微代理：不带令牌请求 `/healthz`。
- **`imctl doctor`**：中文报告，退出码 0 / 2 / 3。守护进程答不了时出兜底报告，分三种原因：连不上、忙（15 秒没应答，不建议重启）、版本太旧。参数有 `--json`、`--offline`、`--refresh`、`--wait`。报告显示联网实测时间；`--refresh` 被节流时说明沿用了哪一轮、几点后才能重测。
- **控制台**：状态页的「体检」面板只在点按钮时运行；修复命令换成本机路径，带复制按钮。
- **最终审查后的修复轮**（结论「修后可合」）：
  - C1：socket 每个连接一条队列；doctor 把超时判为「忙」，轮询失败时保留已拿到的报告；
  - I1：实测结果按配置指纹复用，配置一变就立即重测；
  - I2：守护进程启动后才写入或改过的 `oss.json`、`wecom-proxy.json` 报「重启后生效」，不实测；
  - I3：OSS 签名 GET 的状态码不再丢失，最后的删除重试一次；
  - I4：策略与可读状态在一次加锁中读取；
  - I5：SKILL.md 规定智能体只报告 `nextStep`、不代为执行；
  - 握手探针不会因 SIGPIPE 杀掉守护进程；样例号码换成全零号段。
- **追加（用户 2026-10-12 决定）**：MQTT controller id 默认取本机名（小写，非法字符换成 `-`）。
  - 取值顺序：手填 → 已登记的 id → 本机名。
  - 登记时校验 id 是 topic 的一段；`mqtt.json` 存在却读不了时报错，不猜 id。
  - 控制台在没有已存配置时预填；体检的修复命令只要 broker。
  - 设置页说明改为：首次配置 MQTT 要点「安装 / 更新」。
- **验收中发现、已修**：
  - socket 关闭连接的清理晚于 fd 复用，可能误关下一个连接。这是 C1 引入的，2000 次短连接失败 7 次。现在读到 EOF 当场取消，移除前核对是不是同一个连接。
  - 授权提示补了两种情况：换签名证书后旧条目开关亮着但无效；屏幕录制列表里没有条目时，从访达拖入。
  - 兜底报告给「后台常驻 文件在但没加载」打的 ✔ 改为 ✘。
  - 300 次的释放压力测试已经测不出它要防的回归，又放大了进程级 umask 窗口：换成确定性测试（在服务端自己的队列上调用 `stop()`），压力测试缩到 20 次。
