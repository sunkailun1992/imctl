# B24：`group.addMembers` 打开添加群成员面板的可逆视觉轮次

## 范围

只扩展显式 `group.addMembers` 的“当前群标题栏按钮 → 添加群成员面板”前缀。目标会话选中仍按 B20；成员搜索、选择、`dryRun` 取消、checkpoint、`确定` 与结果取证仍按 B14。模型只可在当轮 AX 确认的右侧标题栏 `AXButton` 中选择一次 `press`，不能决定成员、确认、发送、目标或方法。

AX `AXHelp` / `AXValue` 唯一精确命中“添加群成员”的按钮直接按，零截图、零模型请求。含糊时才进入此入口；按钮仍须是活动群标题的同层控件，位于窗口右侧标题带，可按、启用且不带“完成 / 确定 / 发送”语义。候选外的控件不可执行。

## 有界轮次和后验

- `AIPlannerReversibleRunner` 的普通入口仍只准 `selectRow` / `scroll`；新增入口仅接受方法 `group.addMembers`、目标 `.control(.addGroupMembers)`、定位阶段的 `press`。每命令最多 4 轮、2 次按钮按压、24 秒，另受命令级视觉预算限制。
- 截图前、模型返回后、按压前重新核对：显式外部命令及方法、暂停状态、云端与整窗本机许可、初始与实时策略及原 `.addGroupMembers` 授权、目标身份、企微 PID / 主窗句柄 / frame、活动标题、群成员人数、当前按钮句柄 / role / frame / 可按性。面板已打开后若侧栏人数被遮住，只在面板本身仍为空且标题正确时容许该人数暂时读不到；读到人数变化仍停止。
- 模型选择后重新发现当前 AX 候选。按钮按压后，只有新鲜面板标题为“添加群成员”且已选表存在、行数为 0，才进入 B14 选人流程。模型 `verify` 或 AXPress 返回不构成成功证据。
- 如果按钮打开其它面板，先按该面板的 `取消`，读回窗口没有 `AXSheet`，才允许下一轮。面板结构无法安全取消、取消后未关闭、多个面板或授权 / 窗口漂移时停止。按钮没有打开面板时可在预算内重新观察。

## 边界与验收

不改变协议方法、参数、错误码、事件、MQTT、按键白名单、策略、截图范围或不可逆点。无新发送授权，本批活体验收不作加人或发送。Fake AX 与合成截图覆盖 AXHelp 快路径、丢失首次按压、错误面板取消、方法 / 权限 / 策略 / 窗口 / 标题 / 人数 / 按钮漂移和确认按钮排除；真实企微与 MQTT 证据由主任务单列，未自然触发视觉分支时保持待活体。
