# B40：`client.navigate` 主窗口前后视觉核对 — 源码与 fake 通过，活体待验

## 范围与边界

- 仅显式固定 `client.navigate` 命令，且本机云端视觉和整窗许可开启、菜单 enabled、AX 侧栏能预测一个不同的可见目标时，执行菜单前与菜单后的主窗口观察。
- macOS「窗口」菜单不在企微主窗口截图内。菜单项由既有 `WeComMenuBar` 按 `action` 固定解析、核验身份并 `AXPress` 一次；模型只有 `verify` / `reobserve` / `stop`，不取得菜单项、坐标、侧栏选择或输入能力。
- 每轮以当前企微 PID、主窗口 handle / frame、活动标题及唯一 AX 选中行核验截图；同时检查屏幕录制、整窗云端设置、策略、暂停和命令时限。菜单前后的提供商设置必须一致。菜单后的成功证据仍是 AX 活动标题与选中行，而非模型自评。
- 菜单禁用、视觉关闭或没有可证明的下一个侧栏行时保留原 AX 快路径。`nextUnreadConversation` 仅在当前行之后有可见、数值未读角标时进入视觉分支，其他情况沿 AX 路径。
- 预测后的菜单操作可能因客户端竞争而实际不切换：此时 `changed:false`，可已有一帧菜单前上传，没有菜单后上传。若改到与预测不同的会话或菜单后模型拒绝，则失败而不宣称成功；动作不自动重做。

## 工程验证

- `swift build -q`：通过。
- `swift test --filter B40NavigateVisualTests`：9/9 通过。覆盖前后两轮与唯一菜单动作、菜单禁用零截图、视觉关闭快路径、首轮 stop、次轮 stop、TCC 撤销、策略 / 暂停 / 设置 / 模态框 / 窗口几何 / 时限变化、模型企图选择 AX 行，以及预测后未切换的结果。
- 未改变协议方法、参数、响应字段、幂等、事件或运行数据格式；更新 §6.11 的执行说明。

## 活体边界

本隔离批次没有操作真实客户端、没有上传真实企微窗口、没有发送消息，也没有安装构建。千问实窗双轮、MQTT 终态、活动会话后验及菜单前后截图计数均待主批集成后验收。fake 通过不能作活体结论。
