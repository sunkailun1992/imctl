# B20：四个写入命令的目标选中阶段接入有界视觉轮次

## 背景与范围

B18 已在 `conversation.read` 的会话解析遗漏场景使用有界的可逆“观察 → 选行 → 读回”循环。B19 又要求单步视觉候选在模型返回后、实际 AX 写入前复核授权、目标与客户端状态。本批将同一个**选中目标会话阶段**用于四个已有的固定桌面命令：`message.send`、`message.sendFile`、`group.rename`、`group.addMembers`。命令本身、参数、MQTT / MCP 响应与事件、幂等键和 checkpoint 均保持原样。

范围止于目标会话选中。模型不规划消息正文、文件来源、群名、成员名单、提交按钮或发送时机；四条命令的后续动作及其不可逆点仍由现有处理器、`ActionPolicy` 与 `CommandExecutor` 执行。不能据此宣称四个写入命令已经完成 Codex 式端到端多轮操作，更不能把 fake AX 结果算作企微或 MQTT 活体验收。

## 入口与快速路径

1. 每条命令先按原目标引用解析并核对该命令的写入动作权限：`submit`、`sendFile`、`renameGroup` 或 `addGroupMembers`。`message.sendFile` 保留“核对来源 → 下载到临时 outbox → 选中目标 → 发文件”的顺序；任一失败均清理临时文件。
2. 目标会话已激活时不切换。解析器已给出唯一目标 AX 行时，沿原 `selectConversation` 路径；这两种路径不截屏、不调用模型。
3. 仅当解析器漏掉目标行、侧栏原始 AX 行顶部仍有**唯一精确标题**、命令来源为显式外部固定协议调用、方法匹配且视觉入口启用时，进入 B18 可逆轮次。零匹配按目标未找到处理，多个精确标题按目标歧义失败；不让模型根据头像或相似文字猜目标。

## 可逆视觉轮次契约

1. 轮次仅允许当前目标行的 `selectRow`，或 `reobserve` / `verify` / `stop`。候选来自当轮新鲜 AX 树；模型只返回候选 ID 与限定动作，不提供坐标、自由文本任务、新目标或提交判断。一次命令最多 2 次选行、6 次模型轮次、40 秒，并受已有命令级预算限制。
2. 截图只针对 PID、窗口和 frame 已核验的企微窗口单帧。屏幕录制、`cloudEnabled` 与 `fullWindowEnabled` 三门须全部成立；截图、请求与模型回复仅在内存中使用，不落盘、不进入日志或 MQTT 事件。后台 watcher 与本机媒体方向识别不触发此路径。
3. 截图前、模型返回后和 `AXSelectedRows` 写入前，重核显式命令来源与方法、暂停状态、当前视觉设置、最初政策与当前政策、目标标题及平台身份、`selectConversation` 和本命令的写入动作权限。政策或视觉设置中途变化时，丢弃旧候选。
4. 每轮重新定位企微窗口和唯一精确 AX 行。应用 PID、窗口句柄或 frame、行句柄、角色、目标身份不再相符时停止；旧候选不能跨轮使用。选行后只由新鲜 AX 活动会话头部证明目标已激活。模型 `verify` 不是成功证据。
5. 视觉选中后，各命令再次读取活动会话头部。头部无法证明目标相同则不进入后续写入阶段。若轮次耗尽或证据不足，返回既有失败 / 不确定语义，不用新幂等键自动重试，不触碰发送 checkpoint。

## 安全与验收边界

- 只扩展上述四条命令的目标选中前缀；`conversation.read` 的 B18 分支继续工作。`message.history`、联系人、建群、广播等命令不因共用 helper 获得新的视觉能力。
- 不改 `KeystrokeInjector` 批准按键清单、`ActionPolicy` / `SendPolicy` 语义、白名单、`CommandExecutor`、协议方法 / 字段 / 错误码、传输守卫或屏幕录制范围。
- Fake AX 与假模型须覆盖四命令解析遗漏选中、首次选行未落实后新一轮成功、已激活和已解析的零上传快路径、推理期间暂停 / 政策 / 整窗许可撤销、重名与行消失、窗口与目标漂移，以及写入动作开始前 checkpoint 为空。所有测试使用合成目标与合成图片。
- 真实客户端和 MQTT 验收需分别记录命令终态、活动标题 AX 证据、是否触发真实整窗上传、模型轮数 / 延迟及写入数。常规 AX 路径成功只能证明常规路径；自然未出现解析遗漏时，真实视觉分支仍为**待活体**。没有新的发送条数授权，本批发送数为 **0**。
