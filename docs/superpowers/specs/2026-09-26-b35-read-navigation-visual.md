# B35：读取前的可逆导航主动视觉轮次

## 目标和范围

B34 已在显式 `conversation.read` 的非活动目标选会话上取得真实千问两轮观察、AX 后验及 MQTT 成功证据。本批只扩展两个**确实需要改变企微视图的读取前缀**，不把所有桌面方法改成通用视觉代理：

1. 普通 `message.history`（`scrollback:false`、需要定位最新）在消息区只有**一个可见、可写的竖向 AX 滚动条**且其 AX 值尚未到末尾时，主动让模型选择该 `scroll` 候选。滚动到最新后，重新截取当前企微窗口、请模型作动作后复核，最终用新鲜 AX 滚动条值证明到达底部，再读取最新消息。
2. `contact.request.list` 进入联系人页后，若「新的客户」尚未被选中、左侧 outline 存在**唯一、可见、AX 文本精确匹配**的可操作行，主动让模型选择该 `selectRow` 候选。选行后新鲜截图复核，再用 AX 选中行及新的客户表已出现的组合证据读取申请。`contact.request.accept` 共用这个**只读导航前缀**，但本批视觉模型不能选择申请卡片、接受按钮或执行接受；接受命令后续仍由原动作与原授权、checkpoint、后验控制。

这是显式固定命令内部的可逆观察和导航。MQTT / MCP 的方法、参数、结果形状、策略、幂等与事件语义不变；不增加自由文本任务、模型控制的坐标、按键、发送内容或任意操作。

## 触发与零上传路径

- 只有外部显式命令、该方法的既有暂停 / 策略 / 目标检查、屏幕录制授权、本机 `cloudEnabled` 与独立 `fullWindowEnabled` 都通过后，才可进入本批视觉轮次。每轮使用已核验的企微 PID、单一主窗口、窗口句柄 / frame 和当前方法允许的 AX 候选；图片在内存中送当前选定的官方视觉模型，后台 watcher / 自动申请不上传。
- `message.history` 的滚动条已由 AX 证明在底部时直接读取，不制造截图或模型请求。`contact.request.list` 的新的客户行已被 AX 证明选中、申请表已就绪时直接读取，也不制造请求。`contact.request.accept` 共用这条导航判断；没有导航动作时零上传。
- 整窗视觉未启用时，维持原 AX 导航与读取路径。无唯一可见可操作候选、截图或提供商不可用、模型拒绝、窗口或目标漂移时按原错误语义失败关闭，不用像素位置或模型猜测替代 AX 证据。普通历史的单滚动条主动路径不扩大 `scrollback:true` 的旧历史加载范围；歧义滚动条仍沿原有限视觉后备或拒绝规则。

## 两轮决策和结果证据

首轮模型只得到方法、固定目标、当前相位及限定为一个的 `scroll` 或 `selectRow` AX 候选，可选择该动作、重新观察或停止。模型选出的 ID 在 AX 写入前重新核对句柄、角色、可写性、位置、企微窗口和原策略。滚动只把消息区竖向条写至最新的固定值；选行只设置左侧 outline 的 `AXSelectedRows`。模型不能改变目标、滚动目的值或联系人申请。

实际动作后必须进行**新鲜企微窗口截图与第二次模型决策**。第二轮只可请求 `verify`、重新观察或停止；`verify` 不是成功声明，只触发本机既定后验。`message.history` 须重新定位同一消息区滚动条并读到 AX 值达到底部（允许原实现的浮点阈值），才可将可见消息作为最新页返回。`contact.request.list` 须重新证明唯一精确新的客户 AX 行在 `AXSelectedRows` 中，且右侧申请表已就绪。任一后验失败、模型 `stop`、超预算或中途授权 / 策略变化都不得返回虚假成功；接受命令不得因此进入接受动作。

沿用可逆轮次预算与命令级时间上限；最多两次可逆动作，每次动作之后仍需动作后视觉复核。截图、Base64、模型提示词 / 回复、真实联系人及聊天正文不进入日志、SQLite、MQTT、MCP、测试夹具或文档。`controller.describe` 的 `visionCaptureCount`、`visionRequestCount`、`visionHTTP200Count` 仅为进程级匿名累计，HTTP 200 不代表有效模型选择、AX 后验或命令成功。

## 验收层次与未覆盖项

| 层次 | B35 要求 |
|---|---|
| Fake AX / 假模型 | 两个动作需求均证明首轮选择、AX 动作、新截图模型 `verify`、独立 AX 后验；AX 已满足条件与视觉关闭都零模型请求；候选重复 / 隐藏 / 不可写、模型 `stop`、窗口 / PID / 策略 / 授权变化在动作前或后失败关闭。接受命令的视觉导航失败时不得触碰申请卡片或确认。 |
| 真实企微 + MQTT | 对普通 `message.history` 构造确实离底且只有一个可见可写消息滚动条的样本；对 `contact.request.list` 构造新的客户行未选中的样本。记录每条显式命令前后进程计数差值、两轮动作顺序、AX 后验、MQTT 终态；不保存窗口图或模型原文。若客户端样本不满足触发条件，明确记未触发，不能用配置就绪代替活体。 |
| 回归与发布 | 构建、全量测试、禁用 API 与敏感扫描、文档 / 随包检查分别记录。真实活体、安装包、最终 release 和第二台 Mac 状态须由 B35 门报告单独确认。 |

本批不证明 `message.history` 任意回滚、所有联系人命令或 `contact.request.accept` 的接受动作已完成多轮视觉规划。视觉模型始终是受限的可逆导航助手，结果仍由方法自己的 AX 证据与 MQTT 命令终态决定。
