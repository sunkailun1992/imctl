# B41：联系人申请两次提交前的受限视觉复核

## 目标和边界

仅显式 `contact.request.accept{name,idempotencyKey}` 使用整窗视觉。进入「新的客户」仍用既有 B35 可逆导航；唯一同名待处理卡片、原策略与每小时上限、两个 checkpoint、两个固定 `AXPress`、客户端 `added` 后验和同键幂等保持原实现。模型只可对 AX 已证明的按钮返回 `verify/reobserve/stop`，不能选择目标或执行按钮。

## 执行

1. 第一帧在唯一待处理卡片的「接受」前，冻结企微主窗句柄/PID/位置、卡片内容与按钮句柄/位置；确认左侧「新的客户」仍选中，未有旧备注弹层。视觉失败时不进 checkpoint。
2. 模型复核后重读策略、暂停、录屏和整窗云端开关、同窗同卡片与按钮。原 checkpoint 后再即时核对，固定按一次「接受」。
3. 若出现新备注弹层，只有它位于同一经核验的企微主窗、包含备注标签和唯一「完成」按钮且原卡片仍待处理，才对按钮作第二帧只读复核。旧弹层、独立窗口或多个「完成」按钮均不猜测。
4. 第二轮通过后重做同样的即时授权与身份检查，再由原 checkpoint 与 AX 按一次「完成」。最终成功仍只由卡片 `added` 或从稳定非空列表消失来判定。首个按键后的任何失败走现有不确定 checkpoint 和 `unknown`，不自动重试。

两轮合用显式命令的六轮、40 秒总预算。自动申请轮次和未启用整窗视觉的命令保持零上传。截图、密钥与模型正文不进协议、日志和门报告。真实申请需另有用户明确提供的自有测试对象及活体验收。
