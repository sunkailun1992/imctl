# B20：写入命令目标选中阶段实施计划

> 目标契约见 `docs/superpowers/specs/2026-09-25-b20-mutation-target-visual-rounds.md`。本计划描述实现与验证顺序；结果以 B20 门报告为准。

## 全局约束

- 四个方法只复用**可逆目标选中**；不可逆发送、文件粘贴 / 回车、群名提交和加成员确认仍使用各自既有流程与 checkpoint。先核对原写入动作的策略，再做任何会话切换。
- 保留已激活 / 唯一解析 AX 行的零截图快速路径。视觉后备只在显式外部固定命令、解析遗漏且原始 AX 行顶部标题唯一时启动。
- 延用 B18 的 2 次选行、6 轮、40 秒上限，并叠加 B19 的模型返回后门禁。截图只在本机三门授权和企微 PID / 窗口核验通过后上传所选官方端点；不记录图片、密钥、真实联系人或正文。
- 不修改对外协议、按键、政策语义、幂等、传输守卫、守护进程后台观察与运行数据。没有方法、字段或错误码变化时，协议文档不需要变更。

## Task 1：抽取共用目标选中前缀

1. 在 `WeComCommandHandler` 中让 `messageSend`、`messageSendFile`、`groupRename`、`groupAddMembers` 各自先解析相同 `TargetRef`、检查对应 `ActionKind`，再调用共用 helper，传入固定 `RPCMethod` 和原写入动作种类。
2. Helper 按顺序处理：目标已激活 → 直接返回；解析行唯一 → 原 AX 选行；解析遗漏且原始侧栏行顶部唯一精确标题 → B18 可逆轮次；其它情况维持原失败语义。发文件的下载与 `defer` 清理仍位于方法内。
3. 共用代码只修改目标选中；提交、确认和回执都继续由原动作层完成。视觉轮次返回后重读活动会话头部，未证明原目标则停止。

## Task 2：方法、目标和策略复核

1. 将 B18 轮次参数化为固定方法和该方法已核对的动作种类；仅允许 `conversation.read` 及本批四方法调用，防止其它命令无意进入视觉路径。
2. 每轮 `gate` 核对来源 / 方法、暂停、视觉三门、初始与当前政策、重新解析的目标标题 / 平台身份、`.selectConversation` 与原写入 `ActionKind`。观察和模型调用后再执行同样的门禁。
3. `observe` 只暴露唯一精确标题 AX 行。`apply` 前重新读取 PID、窗口句柄 / frame、行句柄、目标身份、可写性和时间预算；只对当前侧栏表写 `AXSelectedRows`。`verify` 只信新鲜活动头部，不信模型自述。

## Task 3：Fake 集成与回归

1. 用合成 AX 树构造“解析遗漏但原始行顶部标题唯一”的四方法场景；假模型只能选择该行。使后续写入被合成的空输入、非群或注入 checkpoint 中断，证明目标选中先完成而未发生真实发送 / 群变更。
2. 使首次 `AXSelectedRows` 未生效，证明同一命令第二轮重新观察并选中；再覆盖推理期间暂停、整窗许可撤销、原动作政策撤销、重名 / 消失的行、旧窗口与旧句柄，断言拒绝时 AX 写入与 checkpoint 均为零。
3. 对四方法逐一验证已解析 AX 行走直接路径，假截图与模型调用数为零。回归 B18 `conversation.read`、B19 单步视觉门禁、发送幂等 / `unknown`、协议及 `ForbiddenAPITests`。

## Task 4：构建、活体与交付

1. 运行 `swift build`、聚焦 fake、一次全量 `swift test`、`git diff --check` 和 `bash scripts/check-secrets.sh`。门报告记录实际计数、新增告警与基线差异；不得把编译或 fake 成功写为活体验收。
2. 稳定签名安装后，以显式只读 MQTT 和企微 AX 读回确认常规路径与活动标题。四条写入命令的真实多轮分支若无自然解析遗漏，明确记为待活体；没有新发送条数授权，本批不向企微发送消息。真实模型请求数、耗时与终态须来自真实运行证据，不能推算。
3. 分别记录源码提交、构建包 / 签名、本机安装、TCC、MQTT、第二台 Mac 的证据层；未执行的层次保持“未验”。主智能体统一提交推送、重包和 wiki 归档，交接继续列出未接入命令。
