# B21：`message.history` 歧义滚动条实施计划

> 设计口径见同日 B21 规格；本计划不代表活体验收。

1. 在处理器保留唯一 / 几何重合滚动条的既有 AX 快路径。先辨认消息区是否有多个不同位置的可写竖向滚动条，且仅在显式 `message.history` 与 B17 本机设置允许时进入视觉循环。
2. 用 `AIPlannerReversibleRunner` 观察当前企微窗口和滚动条候选。每轮仅允许 `scroll`、重新观察、核验、停止；处理器固定写入 `0` 或 `1`。每次推理前后与 AX 写入前检查当前命令、暂停、策略、活动会话、身份、PID / 窗口和候选。由 AX 滚动条读回证明选条动作落实。
3. 回溯继续使用既有 `loadOlderMessages` 行数等待与恢复流程，但传入视觉轮次验证的滚动条。首轮动作计入滚动上限；之后每次写入与恢复动作重读门禁、窗口及原始候选 frame。将视觉路径的后续滚动限制为 12 次，并受命令级视觉时间预算约束，避免叠加 24 秒模型轮次与 20 次固定滚动造成控制台 60 秒超时。
4. 加 fake AX / 合成截图测试：首写丢失后的二轮落实、回溯选条及恢复、推理中撤销策略 / 切换会话 / 改窗口零写入、首写后撤销策略阻止继续、唯一 AX 路径零上传。运行定向与全量 Swift 测试、守卫及 secret 扫描。
5. 主智能体以已安装签名版做显式只读 MQTT 验收并记录是否触发视觉歧义、延迟、终态与客户端 AX 证据。没有自然样本时保持视觉分支待活体；本批发送数量为 0，且不改变协议或第二台 Mac 授权状态。
