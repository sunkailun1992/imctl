# B18：`conversation.read` 有界可逆视觉轮次实施计划

> 目标口径见 `docs/superpowers/specs/2026-09-24-b18-conversation-read-reversible-rounds.md`。本文是实施顺序，不代表代码、真实模型或客户端已经验收；实测以 B18 门报告为准。

## 全局约束

- 只接入 `conversation.read` 的解析遗漏选行场景。保持现有协议、`CommandExecutor`、策略、身份桥、MQTT 守卫与结果字段；不引入自由文本任务、坐标操作、新按键、新权限或发送。
- 普通唯一 AX 行和已打开目标走直接路径，零截图、零模型请求。视觉循环仅服务于侧栏行顶部 AX 文本精确且唯一、但会话解析器漏掉该标题的情形。
- 每条命令最多 2 次选行、6 次推理轮次、40 秒；模型只提出当前方法允许的 AX 候选 / 可逆动作，成功只由新鲜 AX 活动标题及头部证明。每轮必须复核暂停、策略、身份、PID、窗口和候选；屏幕录制、云端总开关与独立整窗开关都通过才可上传单帧。
- 测试只用合成 AX 树、合成截图与 fake 模型；不得加入真实联系人、消息正文、密钥、broker 地址、原始截图或本机绝对路径。活体仅做只读命令，不发送消息。

## Task 1：封装受限的可逆观察循环

1. 在 `Sources/WeComAdapter/AIPlanner/` 定义一轮新鲜观察、允许动作和执行结果；只允许 `selectRow` / `scroll` 这类可逆步骤。让调用方注入 gate、observe、apply、verify，使循环不自行持有任意 AX 写权限，也不绕过处理器策略。
2. 每轮顺序固定为：限时 → gate → AX 后验 → 新鲜候选 → 方法限定上下文 → 模型选择 → 候选重新验证 → gate 与 AX 后验 → 单一可逆 AX 动作 → AX 后验。`verify` / `reobserve` 仅触发新观察，不算任务完成；`stop`、无效候选与预算耗尽停止。
3. 单测先覆盖两次选行后成功、`verify` 不能伪造成功、模型停止、伪造 ID、动作超限、轮次 / 时间上限和推理后 gate 拒绝，再完成实现。测试注入时钟、截图和模型，不发真实请求。

## Task 2：接入 `conversation.read` 的精确解析遗漏分支

1. 在 `WeComCommandHandler.conversationRead` 先解析原目标、核对策略；目标已激活或已有唯一解析行时继续既有快速路径。只有解析遗漏且侧栏 AX 行顶部有精确标题时，才调用可逆循环。
2. 每轮 `observe` 从当前企微窗口重新读侧栏行，仅暴露唯一精确标题行；多个同名行直接 `TARGET_AMBIGUOUS`，没有行直接目标未找到。模型不能依据视觉猜测哪一个同名会话属于目标。
3. 每轮 `gate` 重解相同 `TargetRef`，比较原目标标题与平台身份，检查 `ActionPolicy` 和暂停；`apply` 再重读表与目标行，确认同一句柄、角色及 `AXSelectedRows` 可写后才选行。`verify` 只读当前活动标题。循环成功后，沿原 `conversation.read` 再读活动头部、消息数量和类型，保持原响应字段。
4. fake 集成测试构造“几何解析漏标题但 AX 文本仍唯一”的侧栏；让首次选择丢失、第二次落实，证明最终结果来自 AX。另测模型返回期间策略撤销或暂停时零选行，并证明普通解析路径不调用模型。

## Task 3：守卫与回归验证

1. 运行 `swift build`、聚焦测试，再运行一次全量 `swift test`；核对 `ForbiddenAPITests`、协议文档守卫、旧 `conversation.read` 与发送路径测试无回归。
2. 运行 `git diff --check` 和 `bash scripts/check-secrets.sh`，检查新增文件与 diff 没有敏感值、截图字节、真实聊天内容或本机路径。若没有协议字段变化，不修改对外协议文档。
3. 门报告区分普通 AX、fake 视觉、真实企微视觉请求三层；普通路径成功时记录模型请求为零，不声称整窗模型分支活体通过。

## Task 4：活体与交付证据

1. 使用稳定签名安装版和已授权的企微，先执行显式只读 `conversation.read`，记录活动标题 AX 后验、命令终态和模型请求次数。活体没有自然出现解析遗漏时，将真实多轮视觉列为未验，不能人为编辑真实会话或发消息来制造样本。
2. 本批若重建应用 / 安装包，分别验证签名、包内版本、本机安装版本与授权；第二台 Mac 尚未装测时如实注明。发送条数写 **0**，与 B17 已获授权且已经执行的本人 1 条测试消息分开。
3. 门报告完成后由主智能体统一提交、推送并更新 wiki 的证据、当前口径与交接；记录源码、测试、活体、安装和目标机是不同证据层。未接入的其余桌面方法及其多轮行为继续列为待办。
