# B59 实施计划

依据 [规格](../specs/2026-10-19-b59-window-image-orientation.md)，修复已由纯合成像素证实的全窗图像翻转，不改变模型否决、AX 成功证据或真实动作授权。

1. **先建立图像回归。** 用明确的 raw RGBA 行顺序生成非对称合成图，直接编码对照应为顶部红色、底部蓝色。解码 `AIPlannerWindowImage.prepare` 的最终 JPEG 后在色块内部取样并容忍 JPEG 量化误差，旧实现应暴露反向结果。补齐非居中窗口、非零/负显示器原点、点/像素比例及最大边缩放的方向与裁切边界断言，不使用真实截图。
2. **检验最终请求图像。** 在现有假 transport seam 中读取真实请求 payload，解码其中的全窗图像，核对上/下与左/右标记方向、候选框和图像位置相符。保持原 allowed steps、无额外 candidate ID、固定方法/目标和 `stop` 契约；不发出真实模型请求。
3. **实施两行修正。** 仅从 `AIPlannerWindowImage.prepare` 删除多余的 translate/负向 scale。保留 source crop、实际图像尺寸换算、背景填充、插值、输出尺寸、编码和大小限制。主流程同步 `1.0.23-dev`、协议、安装说明与门报告；不调整 B37/B55/B57/B58 守卫、策略、checkpoint、权限、早生效核对或其他图像路径。
4. **完成离线验证与独立审查。** 普通测试明确关闭 live 与 live vision，完整非活体测试和守卫测试全部通过后记录精确数量；执行 diff、敏感内容及公开材料检查。独立复核像素证据、裁切范围、请求 payload 和否决路径，不能将合成结果写成现场改名已通过。门报告由主流程填写最终数字与证据。
5. **经 PR 和当前版本 CI 交付。** 开工、提交前和推送前先 fetch；若 main 前进则跟进并重新验证，禁止强推。本人账号在已授权任务内协作，必要 CI 全绿、评审对话解决后按现行例外合并；第三方账号仍须本人对具体版本审核。GitHub 权限、规则、发布与本机操作保留各自授权边界。
6. **核对新候选后受限验证。** 目标为 1.0.23/build 8，CI 通过后按本次既有更新授权构建签章、安装并核对源码、二进制、配置及离线就绪；未完成前仍记录本机安装 1.0.22/build 7。之后只对原获准测试群执行剩余额度内的请求，累计实际改名上限两次，成功后还原计入额度。明确零写入且原名未变的失败允许定位修码后再测；遇 `unknown` 或实际状态不清立即停止，不重试旧记录。用真实终态和客户端后验更新 PR/门报告，分别记录图像方向修正结果与群名功能是否验收。
