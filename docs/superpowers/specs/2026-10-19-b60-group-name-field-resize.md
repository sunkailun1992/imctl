# B60：群名写入后的受限字段宽度变化

本机已安装 B59 对应的 1.0.23/build 8。一次受限群改名请求已跨过首次 AXValue 前的 checkpoint，随后在 verify/round 0 以 staleView 结束，终态为 `unknown`。全部真实写入已经停止。之后使用者明确确认手机已显示请求的新名称，实际改名累计为 1/2，剩余一次仅用于还原；该人工证据不回写原命令为 succeeded，也不恢复自动动作或新增向外改名试验的权限。

## 事实与根因边界

- 事后只读结果显示标题字段包含请求的新名称，而选中的会话列仍显示原名。`activeConversationTitle()` 优先读取标题字段；它不是独立的提交证据。仅凭这组桌面结果不能区分草稿回显与列表迟滞；新增的可信手机人工确认已证明实际名称发生变化，桌面列表尚未反映该状态。
- 当次写值前没有同期字段宽度记录。事后的单次只读字段尺寸不足以证明本次 staleView 是宽度变化造成，不公开真实名称、字段几何、句柄或取样数据。
- 原代码存在可以离线验证的不相容路径：B37 将写后字段与 prepare 阶段完整 frame 比较，动作层的早生效核对也要求写前 frame 完全相同。固定 AXValue 可能使同一标题字段调整宽度；这种变化可能阻断写后观察和早生效核对，进而保留 checkpoint 与 `unknown`。这是需要测试和修复的技术问题，不是已经证实的当次现场根因。
- 手机已生效、桌面原会话列仍为旧名的证据，否定了“旧列名加新字段值必然是安全草稿”的推断。自动写回原值可能成为第二次实际改名，若发生在最后一次还原请求中，还可能超过授权上限。原草稿补偿不能继续作为失败处理；切回其他应用造成的失焦也可能提交编辑，必须一并限制。
- verify/round 0 说明本次验证阶段尚未产生模型轮记录，不得将该拒绝降级为模型可忽略的提示。B59 的图像方向证据及离线回归也不等于群名功能已验收。

## 修改范围与安全约束

1. 新增群名专用的 placement 比较，不修改全局 `sameHistoryFrame`、其他命令或群创建行为。继续要求有限的位置、正宽高、原横向/纵向位置与高度的既有容差，以及字段完整处于原窗口内、会话列表右侧和消息视口上方的标题区域。
2. prepare 和写值前仍冻结完整 frame，包含宽度。只有本命令已知写入固定 AXValue 后，afterStaging 和早生效核对才可使用受限宽度变化；不能把任意值、只读到新名称、焦点变化或异常当作“已经写值”的授权信号。窗口、PID、字段句柄、原会话身份与唯一标题候选保持约束，不能重选另一个同名群或替换编辑器。
3. 不抽取或重写 B37 的 BFS/headerFields。复用原 `stableReader` 的唯一标题候选、直接子模态及 B55 窗口集合核对，维持既有 `allowAppliedTitle` 参数及 `checkCommand` 签名和调用。只有原早生效专用写后 gate 的 `allowAppliedTitle` 为 true，或 `state.afterStagingStarted` 为 true 时，才可进一步要求 `state.beforeVerified` 且字段值精确等于固定 `requestedName`，启用受限宽度例外。prepare/写值前仍完整比较 frame；不新增 `stagedValue`，不允许原值使用宽度例外，不能仅凭 beforeVerified 或当前头部名称放宽宽度。原政策、权限和冻结设置 gate 的位置与语义不变。
4. 删除动作层的 `restoreStagedNameIfOwned` 及所有失败补偿调用，不新增恢复 hook。checkpoint 后的模型 stop、非法选择、守卫拒绝或 confirm 错误保持原错误传播，由既有执行器保留不确定性；不得通过写回原值、确认、失焦或重试来清理现场。动作层早生效核对采用同一受限 placement，并继续独立核对原窗口、PID、字段、原会话行、已知请求值与标题区域；不能用几何相容忽略位置或高度变化、失效元素及模态冲突。
5. 早生效成功仍须原选中行句柄更新为唯一请求新名、字段和头部一致、请求新名在入口时不存在，以及原政策、权限、冻结设置和视觉 gate 全部通过。字段回显本身永远不够。模型 `stop`、非法选择、授权撤销、预算或设置变化均不得被宽度相容、捕获异常或新名称掩盖；已生效时不追加 confirm。
6. B57 可见窗口准备只新增只读的 `restoreFocus` 判定。公有 handler 在调用 checkpoint 回调前先记录本地“已尝试 checkpoint”标志，只有取得 `verified == true` 的动作结果后才记录已验证。checkpoint 后出现错误、回调本身抛错、afterSubmit 崩溃或返回未验证结果时，均不调用 `restoreFrontmost`；写入前尚未尝试 checkpoint 的失败，以及正常已验证成功，仍按既有行为恢复原前台应用。此判定不读取标题来猜测提交状态，不新增 AX 动作或客户端写入。
7. checkpoint 仍在首次可能生效的 AXValue 前且只记录一次；本地焦点保护标志不替代落盘 checkpoint，也不改变幂等回放、状态/outcome、`unknown` 后停止、崩溃传播及不可逆提交次数。诊断继续使用固定类别，不加入真实名称、联系方式、字段几何、句柄、截图、模型原文、密钥或本机路径。

7. 正常 confirm 后也须绑定首次写值前保存的原 row handle，不能仅凭另一个 selected row 的相同新名称判断成功。等待原列表后验未满足时，原有固定 blur 必须先重新通过同一原会话/字段和值核对；失去选中行或切到另一同名群则停止，不移焦探测。群创建保持原有新行后验。

## 离线验收

- 用 fake AX 在固定 AXValue 后模拟同一字段宽度增长与缩小，证明写后观察可继续；只回显新值、原会话列仍为原名时不得提前判成功，正常路径仍依模型许可和原提交后验完成。
- 写值前宽度变化，以及写后的位置/高度、窗口、PID、字段替换、越界、多候选、未知值和同名其他会话，继续拒绝；不以更大的全局容差让测试通过。
- 覆盖受限宽度变化下的早生效唯一原行证据、模型 stop/非法选择、所有权漂移、授权撤销及 afterSubmit 崩溃。checkpoint 后拒绝均断言零补偿写值，保持原错误及模型否决；不能因为仍看到旧列名而写回原值。
- 经公有 handler 和 off-Space fake 覆盖第二轮 stop：checkpoint 一次、请求值只写一次、无 confirm、无补偿和无前台恢复；checkpoint 回调抛错时零字段写入且不恢复焦点；afterSubmit 崩溃保留原类型且不恢复焦点。保留原有写入前 stop 和正常 verified 成功恢复原前台的回归，区分保护边界与全面禁用恢复。
- 完整非活体测试、守卫测试、扫描及独立 review 的精确结果由门报告和 PR 记录。合成测试只验证代码契约；已获手机人工确认的实际改名、旧命令的 unknown，以及仍待现场验证的根因/修复效果和安全还原分别记录。
