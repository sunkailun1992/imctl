# 换 Mac / 换屏幕：几何与前台的可移植性手册（B9–B11）

## 原则

- 定位先用当前 AX 角色、可设属性、父子关系和实际 `frame`；几何只用于证明候选属于当前窗口及控件区域，不写绝对屏幕点击坐标。B9 消除了五处绝对屏幕坐标；B48 进一步让「新的客户」行 / 卡片表跟随大纲与滚动区域，让会话「+」跟随同父搜索栏，重复候选时停止。B49 把后台通讯录角标、群名表头、「新的客户」页「添加」、邀请打招呼框和群成员人数改为实时关系：角标按「按钮 + 2×2 锚点」成对与等距锚点列归属；表头以消息视口上沿为界；「添加」须是页头标题的同父兄弟且同行；打招呼框只在确认按钮自己的弹层 / 窗口里且唯一；「群成员·N」只认消息视口右缘以右的侧栏。B16 的表头按钮裁图边界（上传隐私门）保留原窄带，布局不符时不上传。
- 前台判断用 NSWorkspace 前台 pid + 客户端 `AXFrontmost`，不看屏幕；每次 pid 级按键前重新置前（`withFront`），发送后交还前台。
- 多屏时窗口 `minX` 可以是 1920、`minY` 可以是负数，消息表 `y` 也常为负（滚动后）；所有判断都不能假设 `x ≥ 0`。
- B16 的历史边界是只传右侧标题栏按钮裁图。B17 在本机单独授权后可为显式固定桌面命令上传经核验的**企微主窗口**：用 PID、AX 窗口及显示缩放裁掉其它应用像素，模型只能选本轮 AX 候选，操作前再核对窗口、会话、元素角色与位置；无法核验就停。不同缩放、跨屏和窗口移动必须通过 B17 门报告实测，不能由 `setup --check` 推断。

## 换机 / 换屏后先看什么

```bash
imctl doctor                       # 逐项就绪：能不能用、卡在哪、怎么修（先看这个）
imctl call controller.diagnose     # trusted、windowFrame、conversationTable、messageTable、composerPresent、rowHeights
imctl call controller.permissions  # 授权是否还在
imctl probe messages               # 行分类是否正常（message / media / system / timeSeparator）
imctl probe rail                   # 导航栏角标能否归属到「通讯录」；unknown 时后台不启动自动接受轮次
```

2026-09-16 实录：企微搬到第二块屏（`windowFrame (1920, 0, 1920×1080)`，`messageTable (2330, -1046, 1511×1942)`）后，会话读取、通讯录导航（⌘8 / ⌃Tab 两步到 新的客户）、`conversation.read`、图片行识别全部正常，无需改代码。

MQTT：新 Mac 第一次登记时，controller id 默认取本机名，与旧 Mac 不同。Java 端如果按旧 id 发命令，旧机又已停用，登记时显式填旧 id：`imctl enroll --broker … --controller-id <旧 id>`，或在控制台设置页改。两台同时在线的 Mac 不能共用一个 id。

## 需要重录夹具的情况

客户端版本变化（当前 5.0.11）、行高 / 布局变化（`rowHeights` 不再是 64）、通讯录签名文字变化。夹具用 `imctl dump-tree`（默认脱敏）录到 `Tests/Fixtures/ax-trees/`，`GeometryPortabilityTests` 会把夹具整体平移 / 收窄后重跑定位——新夹具也要能通过它。

## 已知未验证

- 只在本机 1920×1200 + 第二屏 1920×1080 上活体过；Retina 缩放不同的 Mac 未验证（AX 坐标是点不是像素，预期无影响）。
- 客户端窗口极窄（< 1000 点）时会话表 / 消息表的高度选择规则未验证。
- B16 的不同缩放、跨屏、异地 Mac 的裁图坐标与外部 API 时延尚未验收；`setup --check` 的屏幕录制通过不证明云端视觉可用。
- B48 的动态行 / 表 /「+」改动已通过本地合成布局测试，本机只读 AX 树证实搜索栏与「+」为同父控件；第二台 Mac 和不同缩放未做活体。
- B49 的导航栏角标：导航项没有 AX 文字，「通讯录」靠两条 5.0.11 录制事实同时成立来认（客户端列出的第 2 对；等距锚点列第 10 格，与 9/15 实录的导航栏顺序和 ⌘8 后两步 ⌃Tab 一致）。用户自定义导航栏顺序、元素读取出错或结构存疑时一律 unknown（沿用上次已归属的计数、不喂给自动接受触发器，恢复后也不算升高），后台不自动进通讯录；客户端版本本身不检查，升级后两条事实仍成立才继续认；换一台导航栏顺序不同的 Mac，自动接受会停在 unknown，需要先用 `imctl probe rail` 看清再定。窄栏上角标 > 0 的真实样本仍待一次新的客户申请来核对。
