# B23：申请列表的“新的客户”可逆选中轮次

## 范围

显式 `contact.request.list` 与 `contact.request.accept` 进入通讯录后，仍先用原 AX 导航和“新的客户”行解析。直接选中后由 `AXSelectedRows` 与右侧卡片表共同读回；解析遗漏或选中后验未落实时，只有左侧 `AXOutline` 内存在**唯一精确“新的客户”AX 行**，才进入有界视觉轮次。正常 AX 路径零截图、零模型调用。`contact.list`、`contact.add`、后台申请自动轮次及其他命令维持原路径。

模型只可在当轮 AX 候选里选择该行的 `selectRow`，或 `reobserve` / `verify` / `stop`；不能按“接受”、备注“完成”或其它按钮，不能修改申请姓名、策略或命令参数。右侧同名标题不属于 AXOutline，重复精确行则失败，不由模型猜。一个显式命令最多 4 个视觉轮次、2 次选行、24 秒，并受命令级视觉预算约束。

## 授权和结果

每轮截图前、模型答复后及最后一次 AX 写入前，重验显式来源与方法、暂停、云端与整窗开关、当前与初始策略、`openContacts`（接受命令另验 `acceptRequest`）、企微窗口 PID / 句柄 / frame、当前通讯录视图、唯一 AX 行角色 / 句柄 / frame 和可写 `AXSelectedRows`。截图仅为已验证企微窗口单帧，数据留在既有内存路径。选行后由新鲜 AX 选中行与卡片表证明结果；模型答复本身不构成成功。

`contact.request.list` 的空列表仍须右侧卡片区域出现明确空态并稳定读回；空白表不算零申请。`contact.request.accept` 仍在导航完成后要求唯一同名 `pending` 卡片，并沿原 checkpoint、按钮复核、备注弹层与接受后验；视觉轮次不会重试这些不可逆步骤。协议、策略、MQTT 结果 / 事件与按键集合均不变。

假件测试用于证明选中与撤销边界；真实企微、云端视觉和 MQTT 结果需在门报告单独记录。没有新的活体接受授权时，本批接受数为 **0**。
