# B28：发送准备阶段的 AX 证据边界

## 目标与范围

显式 `message.send` 和 `message.sendFile` 已在 B20 对目标会话选中支持有界视觉轮次；本批检查目标选中之后、不可逆提交之前的编辑框与暂存内容。命令正文、文件来源、收件人、一次提交、checkpoint、外发气泡后验、MQTT / MCP 契约均沿原路径。

真实 5.0.10/5.0.11 AX 夹具只证明：聊天消息视口下方有一个可写 `AXTextArea`。它们没有给两个底部可写编辑框提供可独立读回的“哪个是聊天输入框”语义，也没有给暂存附件提供可绑定到指定文件的 AX 标识。模型看图选一个编辑框或看到内容变化，都无法由 AX 证明这个选择/变化就是本次要发送的内容。因此本批**不启用编辑框写入或附件粘贴的模型动作**；含糊时在发送前停止，保持正常 AX 路径零截图。未来若真实客户端提供独立可读回的编辑框身份或附件 chip 证据，才能另立规格放开方法专属轮次。

## 发送前守卫

1. 只有处于会话表右侧、消息视口下方、且位于企微窗口内的可写 `AXTextArea` 能成为输入框。唯一匹配沿 AX 快路径；多个匹配为 `ambiguous composer`，在任何正文写入、粘贴、checkpoint 或 Return 之前失败。窗口其它位置即使有面积更大的可写编辑框也不能取代它。
2. `message.send` 设入调用方提供的原文并读回后，在不可逆提交前重读活动会话和同一输入框，并要求其值仍是原文。若用户改了草稿或会话漂移，不能发出，也不能清理不是本次原文的内容。失败时只有活动会话和输入框仍相同、值仍为本次暂存原文时才可清理；旧句柄上的他人草稿不清理。
3. `message.sendFile` 保留来源校验、临时 outbox 与一次 `⌘V`。粘贴等待期间若输入框出现文本值，视为草稿变化，停止且不按 Return；无附件暂存信号时停止。不可逆提交前重读活动会话、同一输入框、空文本值和暂存信号。这个信号仍只是 AX 中字符数/子元素变化，**不能证明文件身份**；没有更强 chip 证据时不让模型猜，活体回归需单列。
4. Return/其它提交动作之后若消息表读取失败，文本发送保持 checkpoint 的 `unknown`，不把 `CLIENT_UNAVAILABLE` 映射成可盲重试的失败；已有相符外发气泡仍可成功。无后验且内容可能已发出时不自动换幂等键重试。

## 门与验收

- 不修改 `ActionPolicy`、`SendPolicy`、编译白名单、`CommandExecutor`、`KeystrokeInjector`、模型通用 runner、屏幕录制范围或协议文档；B20 目标选中视觉轮次不受影响。
- Fake AX 用例覆盖：窗口其它区域的大编辑框不能抢占、底部双编辑框零写/零粘贴/零提交、文本读回后人工改动被保留、发文件粘贴时出现文本不提交、提交后 AX 行读取失败为 `unknown`。正常唯一输入框沿既有无截图路径。
- 本批子工作树不操作真实企微、不发消息。真实客户端布局/附件暂存和 MQTT 终态由主任务部署后另做授权范围内的验收；没有新增发送授权时发送数为 0。
