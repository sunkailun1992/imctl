# B59：纠正全窗视觉图像的垂直方向

本机已安装 B58 对应的 1.0.22/build 7。随后一次获准的群改名请求进入原 B37 prepare/round 1，模型返回 `stop`；checkpoint 为 0，原群名未变，实际改名累计仍为 0/2。该请求的全窗 capture/request/HTTP 200 增量均为 1，原先的 staleView guard 拒绝未在这次请求复现。模型拒绝后已经停止，没有将该记录换键重试。

## 已证实的图像问题

离线对照使用纯合成的 400 × 300 raw RGBA 图像，首行红色、底行蓝色，不含真实窗口、聊天、名称或密钥。直接 PNG 编码的对照方向正常；经过当前 `AIPlannerWindowImage.prepare` 后，解码得到的 JPEG 顶部为蓝色、底部为红色，证明全窗图像被上下翻转。仅移除 bitmap context 的 `translateBy` 与 `scaleBy(y: -1)` 两次变换后，解码结果恢复为顶部红色、底部蓝色。

这项合成证据证明的是共享全窗图像编码边界存在方向错误，不能证明它就是现场模型 `stop` 的原因。现场没有保存模型原文或真实上传图像；模型停止的因果关系、修正后能否完成群改名，仍待新版本受限验证。capture/request/HTTP 200 计数以及离线测试通过都不是改名成功证据。
