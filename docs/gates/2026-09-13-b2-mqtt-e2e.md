broker：用户提供的 LAN EMQX 5.9.3（地址与仪表盘凭据只存本地 `~/Library/Application Support/imctl/mqtt.json` 与本对话，不入库）。核对：MQTT 客户端**无认证链（匿名可连）**，authz `file` 源且 `no_match=allow`，监听 tcp 1883 / ws 8083 / ssl 8883 / wss 8084，核对时 0 连接。企微客户端在本批中间自动升级到 **5.0.11**。

## 实现

- `MQTTBinding`（纯逻辑）：`…/cmd` 上的 JSON-RPC 2.0 → `RPCDispatcher`；响应发到 MQTT 5 Response Topic（缺省 `…/rsp`），回显 Correlation Data，user property `controller_id`；事件泵按 `event_id` 顺序 QoS 1 发布到 `…/evt`，游标存 `kv` 表、只在发布成功后前进；`…/state` retained（online/offline/pid）+ 遗嘱。
- `MQTTNIOLink`（mqtt-nio 2.13.0，v5）：`cleanStart=false` + `sessionExpiryInterval=86400`（离线期间 broker 缓存 QoS 1 命令，重复投递由幂等键吸收），订阅 cmd QoS 1，命令在串行队列执行（不阻塞事件循环），250 ms 事件泵，断线指数退避重连（1→30 s）。
- CLI：`imctl enroll`（写 0600 设置文件）、`imctl mqtt call <method> --params`（自带回复 topic + correlation，充当最小 Java 消费方）、`imctl mqtt tail`。`imctld run --mqtt`。
- 连带修正：会话表/消息表/输入框都可缺（5.0.11 刚启动无活动会话，只有会话表）；`account.status` 报 `clientRunning`；watcher 在客户端不可达/恢复时自动加/清 `system` 暂停并发 `controller.state`；watcher 在会话切换、区域缺失或每 60 次轮询后重定位布局；切换会话那一轮不把整屏历史当新消息推出。
- `swift test` 131 个测试（新增 MQTT 绑定 8 个、kv 1 个、5.0.11 夹具 2 个、observable 过滤 1 个）。

## 结论与未闭环

- 阶段 2 的"传输"部分通过：MQTT 5 语义（Response Topic / Correlation Data / 持久会话 / retained + will / QoS 1 + 幂等）在 EMQX 5.9.3 上成立；Java 侧只需订阅 `im/{id}/evt`、发布到 `im/{id}/cmd` 并处理 `…/rsp` 或自带 Response Topic。
- 未闭环：broker 当前匿名开放（阶段 2 的 `enroll` 凭据 + 每机 ACL 待在 EMQX 上配置）；共享订阅由 Java 侧决定组名；`origin: other` 接管信号未做；LaunchAgent 常驻与 7 天运行未做；AXObserver 通知路径仍只在 `probe watch`。
- 企微 5.0.11：会话表/消息表/输入框结构与 5.0.10 一致（夹具 `wecom-5.0.11-main-window.json`），解析与发送无需改动。
