# B56：澄清群名被动观察的模型提示

用户要求修复群改名误报，并追问已重装版本是否真正修好。B55 已按本人批准的固定 head 和全绿 CI 合并、安装；之后一次受限请求在写值前由模型返回 `stop`，实际改名为 0。用户要求前置失败即停止，因此本批不再请求真实客户端或视觉提供商，也不换键重试该记录。

只读代码审查及新增 payload 测试确认三处提示歧义：群名的被动观察候选被统一称为 `Actionable AX candidate boxes`，而专属提示又禁止模型写入；`another group or editor` 没有排除正常侧栏其他会话与下方聊天输入框；验证阶段还会夹带“单个候选本身不证明标题匹配”的通用选择提示，与该阶段已经独立读回固定暂存名的上下文不符。没有保留真实截图或模型理由，不能认定这就是那次 `stop` 的原因。

本批仅在 `group.rename / groupNameField`、prepare 或 verify、允许步骤全部属于 `verify / reobserve / stop` 的既有被动轮中澄清：

- 唯一群名候选框是只读观察锚点；`writeText` 只表示本机 AX 可写能力，不授权模型写入。
- 正常侧栏会话、会话消息与下方聊天输入框不是替代的群名编辑器。模型只核对原活动群标题区里的候选。
- 候选不在活动群标题区、活动群冲突、另一个竞争的群名编辑器或遮挡标题区的冲突弹窗仍须停止；画面未稳定可重看，证据不确定仍可停止。
- 模型不可写群名、提供新标题、确认或宣告成功。解码器和 runner 原样保留 `candidateID == nil`、白名单、stop veto 与 AX 后验；不改变策略、权限、截图范围、checkpoint、幂等、字段或窗口检查。

用合成 AX / 图像和假 transport 检验真实请求 payload，覆盖千问与 Gemini、准备与验证阶段；严格解码与 B37 动作层回归证明停止和非法选择仍拒绝。离线通过不能写成真实改名成功。本批经分支 / PR 由本人审核，新版本安装与新请求另按明确批准执行。
